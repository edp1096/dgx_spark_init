# DeepSeek 업데이트 검증 — 2026-09-09

DSML 복구는 기본 적용하고, SWA 초안 캐시 보완은 선택 기능으로 유지한다. 세 설정 각 18개, 총 54개 응답을 생성했다.

| 요청 | 기준 중앙값(s) | DSML만(s) | SWA+DSML(s) |

| repeat_json60 | 1.684 | 1.700 | 1.693 |
| repeat_long_facts | 0.887 | 0.901 | 0.890 |
| korean_arithmetic | 0.549 | 0.549 | 0.554 |
| tool_auto | 0.972 | 0.981 | 1.126 |
| tool_required | 1.124 | 1.145 | 1.139 |
| tool_none | 0.402 | 0.332 | 0.545 |

세 설정의 내용·도구 인자는 18/18 모두 정답이고, 기준 대비 원문·호출 인자도 18/18 일치했다. 강제 도구 호출 3건은 인자가 맞아도 종료 사유가 `stop`이어서 엄격한 프로토콜 검사는 각 15/18이다. 이 기존 문제를 이번 패치가 고쳤다고 보지 않는다.

DSML만 켠 경우 지연은 기준과 비슷했다. 두 패치를 같이 켜면 짧은 자동 도구 호출과 도구 미사용 요청이 약 0.15초 늘었다. 이 표본에서는 SWA 보완이 해결하는 반복 출력 고장을 재현하지 못했으므로, 자동 적용할 속도 이득은 없다. DSML의 잘못된 외부 표기 복구는 37개 CPU 회귀검사, SWA 보완은 16개 CPU 회귀검사로 별도 확인했다.

## 조건과 범위

- 공식 Vision-Exp 가중치와 기존 Anemll 이미지 pin 유지. C128A는 세 설정 모두 켬.
- 상한 128K, 슬롯 2, batch 4096, utilization 0.78, temperature 0. 요청은 순차 실행했다. 실제 1M 입력이나 동시 부하 검증은 아니다.
- 반복 3회는 독립 문항 18개를 뜻하지 않는다. 첫 긴 입력과 캐시 재사용 요청을 함께 보존했다.
- 로딩 중 swap과 생성 중 swap을 구분해 기록했다. 완료한 세 실행 중 호스트 재부팅은 없고, 종료 후 모델 컨테이너를 제거했다.
- 이 작은 텍스트·도구 표본으로 광범위한 에이전트 성능이나 영상 입력 품질을 보장하지 않는다.
