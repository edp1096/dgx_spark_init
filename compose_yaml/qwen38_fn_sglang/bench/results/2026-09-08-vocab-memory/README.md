# Flash Next 초안 어휘 메모리 비교 — 2026-09-08

64K·128K·전체 어휘를 비교한다. **컨텍스트 길이 비교가 아니다.**
전체 모드는 `off`이며, 이 모델은 유효 토크나이저 ID 248,077개와 출력층 248,320행을 가진다.
262,144개짜리 어휘를 새로 만들지 않는다.

## 실측 전 추정

실행 이미지의 `eagle_worker_v2.py`와 `qwen3_5_mtp.py`, 모델 BF16 헤더를 읽었다.
출력층은 `[248320, 2560]` BF16이며 본체에 필요한 원본 크기는 1,271,398,400 bytes다.
전체 어휘 모드는 이 원본을 MTP와 공유한다. shortlist 모드는 원본을 잠시 clone한 뒤
선택한 행을 별도 텐서로 보관한다.

| 모드 | 별도 보관 출력층 | 초기 clone+선택 텐서의 일시적 추가 크기 |
|---|---:|---:|
| ko64k | 320 MiB | 약 1.497 GiB |
| ko128k | 640 MiB | 약 1.809 GiB |
| full / off | 0 (본체와 공유) | 0 |

이 값은 해당 출력층 복사 비용이며 전체 엔진 메모리가 아니다. KV, Mamba 상태,
logits, CUDA graph, CUDA allocator 예약 및 파일 매핑은 별도다. 자세한 추정 조건은
`estimate.json`, 원본 지문은 `source-hashes.json`에 기록했다.

## 고정 조건과 보호 장치

- 기존 `dgx-sglang-qwen38-fn:sm121-vocab1` 이미지와 현재 NVFP4 가중치 사용.
- TP1, context 65,536, MTP NEXTN 3 steps / draft 4 tokens / top-k 1.
- KV pool은 **max_total_tokens=65,536**, Mamba slots는 **18**로 고정.
  운영 기본값인 자동 KV pool과는 다르다. 자동 배분에 의한 어휘별 KV 크기 차이를
  제거하고 메모리 여유를 확보하기 위한 실험 설정이다.
- 각 모드를 하나씩 임시 컨테이너에서 실행, 테스트 API는 localhost:18000.
- production 컨테이너는 시작 전 정지 상태이며 건드리지 않는다. 지원 서비스 4종 유지.
- 시작 전 MemAvailable 110 GiB 이상 필요. 0.25초마다 메모리를 감시하며
  MemAvailable 16 GiB 미만, swap 512 MiB 이상 증가, 감시 실패 시 테스트 컨테이너 kill.
  다른 컨테이너가 시작되는 경우에도 테스트를 중단한다.
- Docker 메모리 제한은 기존 값 유지. 이 장비에서 GPU 할당은 Docker 통계만으로
  파악할 수 없어 `/proc/meminfo`와 PyTorch 할당 통계를 함께 기록한다.
- 메모리 부족·swap 증가·감시 오류 중단 경로를 합성 값으로 먼저 검사했다.

## 측정 범위

64K 목록은 기존 `draft_vocab.json`과 동일한 ID로 재생성했다. 128K는 같은 자료와
선정 규칙을 사용했다. `ko64k.json`, `ko128k.json`에 해시·정책·별도 자료 포함률을 둔다.
측정 전용 패치는 출력층 초기화 전후 CUDA 할당량과 실제 공유 여부만 기록하며
가중치 계산·추론 정책을 바꾸지 않는다. `measurement-only.patch`를 참고한다.

각 모드에서 기동 → 준비 후 30초 대기 → 기존 합성 workload 1회 → 30초 대기를 수행한다.
workload는 8개 단일 요청, 도구 호출 형식, 이미지, 동시 요청 2개와 약 35K 입력을 포함한다.
메모리 비교가 주목적이며 1회 속도 수치는 참고값이다. 64K 최대 입력·최대 동시성의
모든 조합을 검증한 것은 아니다.

호스트 추가 사용량은 **각 모드 시작 전 MemAvailable − 측정 시 MemAvailable**로 계산한다.
순수 가중치 크기·nvidia-smi 전용 메모리·영구 상주량과 구분한다. 유휴 메모리는 중앙값,
피크는 0.25초 표본의 최대값으로 기록한다. 표본 사이의 순간 피크를 보장하지 않으며,
출력층 생성의 순간 피크는 별도의 CUDA peak allocation 기록으로 보완한다.

## 실측 결과

세 조건 모두 완료했다. 단위 GiB는 2³⁰ bytes이며 아래 전체 사용량은 모델이 없던 상태 대비
호스트 가용 메모리 감소량이다. 준비 직후와 실제 요청 처리 후의 유휴값을 구분했다.

| 초안 어휘 | 출력층 복사본: 추정 → 실측 | 준비 직후 추가 사용량 | 처리 후 추가 사용량 | 로딩·처리 포함 최대 추가 사용량 | 최저 가용량 |
|---|---:|---:|---:|---:|---:|
| 64K (65,536) | 320 → 320 MiB | 91.62 GiB | 90.83 GiB | 96.24 GiB | 20.78 GiB |
| 128K (131,072) | 640 → 640 MiB | 91.76 GiB | 91.23 GiB | 96.24 GiB | 20.86 GiB |
| 전체 / off (출력층 248,320행) | 0 → 0 (공유) | 91.30 GiB | 90.55 GiB | 96.43 GiB | 20.68 GiB |

- 64K→128K: 실제 출력층 복사본 +320 MiB, 인덱스까지 포함한 초기화 후 CUDA 할당은
  +320.5 MiB였다. 호스트의 처리 후 추가 사용량 차이는 약 +0.41 GiB다.
- 전체 어휘는 본체 출력층과 실제 데이터 포인터를 공유한다. 처리 후 사용량은
  64K보다 약 0.27 GiB 작았다. 전체 어휘가 자동으로 가장 많은 메모리를 쓰는 구조가 아니다.
- 전체 엔진 피크는 약 96.2–96.4 GiB로 거의 같았다. 본체·MTP 가중치 로딩과 공통 버퍼가
  피크를 지배하므로 출력층 복사본 크기만으로 전체 피크를 예측하면 안 된다.
- 출력층 초기화 중의 순간 추가 CUDA 할당은 64K **1,533 MiB**, 128K **1,853.5 MiB**,
  전체 **0 MiB**였다. 사전 추정의 clone+subset에 각각 0.5/1 MiB 토큰 ID 배열이 추가된다.
- 모든 시험 컨테이너에서 cgroup OOM/oom_kill=0, Docker OOMKilled=false. 감시 중단 없음.
  전체 최저 MemAvailable은 **20.68 GiB**, 설정한 중단선은 16 GiB였다.
- 실제 감시 표본 간 최대 간격은 0.286초 이하였다. 세 조건 모두 6개 기능·부하 검사 통과.
- 시험 종료 후 가용 메모리는 약 **117 GiB**로 회복했다. 원래 모델 컨테이너는 정지 상태를
  유지했고 지원 서비스 4종의 컨테이너 ID·상태도 보존했다. 운영 설정은 바꾸지 않았다.

### 참고 속도 (단회)

같은 8개 짧은 입력에서 출력 토큰 합계 / 요청 시간 합계다. Thinking off이며 입력/API 시간도
포함한다. 메모리 시험에 부수한 1회 수치이므로 작은 차이를 확정적인 속도 우위로 보지 않는다.

| 초안 어휘 | API 처리량 |
|---|---:|
| ko64k | 33.10 tok/s |
| ko128k | 32.09 tok/s |
| full | 28.91 tok/s |

128K는 이 시험에서 64K보다 약 3.1% 느렸으며, 전체 어휘는 약 12.7% 느렸다.
새 어휘 목록의 범용 품질 우위를 검증한 시험은 아니다. 운영 기본값 ko64k는 그대로다.

### 결과 재계산

```sh
python3 bench/summarize_vocab_memory.py bench/results/2026-09-08-vocab-memory
```

`summary.json`은 원본 `*-memory.json`, `*-benchmark.json`, `*-telemetry.jsonl`에서 계산한다.
`*-launch.json`은 실제 명령, `*-server-info.json`은 실행 설정, `*-server.log`는 로딩·할당 로그다.
`complete.json`은 세 조건 완료 및 기존 서비스 보존 확인이다. 다른 장비/커밋으로 재시험할 때는
새 출력 디렉터리와 해당 이미지에 맞는 계측 패치·어휘 지문 검증이 필요하다.

스왑은 소량 증가했으며 각 조건의 시작 대비 최대 증가량은 ko64k 77.8 MiB, ko128k 38.4 MiB, full 51.6 MiB였다. 512 MiB 증가 중단선에 도달하지 않았다.
