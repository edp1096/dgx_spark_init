# TP2 MTP·프리필 청크·한국어 출력 비교 (2026-09-15)

대상은 Huihui-RadixArk NVFP4, DGX Spark 2대, SGLang, BF16 KV, 1M 문맥이다. Catplusplus MTP와 모델 재양자화는 사용하지 않았다.

## MTP shortlist

참고: [tonyd2wild 구현, 고정 커밋 6ad1c8f](https://github.com/tonyd2wild/Qwen3.8-Flash-Next-NVFP4-DGX-Spark/tree/6ad1c8f15cbab1ababd2048e8e5f94094dbfc4a0)의 축소 어휘 TP 소유권 처리. 여기서는 연속 토큰 ID 범위 대신 한국어 shortlist의 임의 토큰 ID를 균등 분할했다.

TP2의 전체 초안 어휘를 ko64k로 줄인다. 원본 어휘의 랭크별 소유권에 따라 출력층 행을 모은 뒤 shortlist 순서로 각 랭크에 32,768개씩 배분한다. 시작 때 한 번 수행하며, 본체의 전체 어휘 검증·원본 가중치는 유지한다. CPU 2-rank 참조 검사에서 비연속 토큰 ID의 logits가 정확히 일치했다. GPU 실행에서도 양쪽 분할 크기를 확인했다.

한국어 4종 × 2회, 응답당 256토큰의 총 생성 토큰/총 생성 시간 기준 tg는 **38.10 → 40.75 tok/s (+7.0%)**였다. 짧은 코드·JSON은 같은 개선률을 보이지 않아 이 수치에 포함하지 않았다. 일부 응답은 길이 제한으로 끝났으며 전반적인 품질 평가가 아니다. 요청별 sampling seed는 서버의 deterministic 모드가 꺼져 있어 동일 난수를 보장하지 않는다.

## 청크 비교

각 설정에서 캐시를 비우고 25,246 / 100,846 / 201,647토큰 입력을 두 번씩 조회했다. 표의 TTFT는 두 번의 중앙값이다.

| 초안 어휘 / 청크 | 25K TTFT | 101K TTFT | 202K TTFT | 정답 |
|---|---:|---:|---:|---:|
| 전체 / 1024 | 10.35초 | 43.82초 | 95.01초 | 6/6 |
| ko64k / 1024 | 10.50초 | 43.38초 | 94.25초 | 6/6 |
| ko64k / 2048 | 8.64초 | 38.32초 | 81.73초 | 5/6 |
| ko64k / 4096 | 8.26초 | 34.48초 | 75.61초 | 2/6 |
| ko64k / 8192 | 8.68초 | 33.75초 | 71.15초 | 1/6 |

**2048·4096·8192는 제외한다.** 틀린 응답은 `!`만 32개 반복했다. 실패를 포함한 위 시간은 유효한 성능 개선치로 취급하지 않는다. 2048의 실패 입력은 즉시 재시험하면 4/4 통과해 간헐적임을 확인했다. 1024에서는 pp 개선이 사실상 없다.

QSA top-k 난수 180건·경계값 150건, B12X 출력층 GEMV 40건은 통과했다. 네이티브/채팅 API와 스트리밍 유무도 비교했으나 원인을 특정하지 못했다. 프롬프트 tokenization은 로컬/서버가 25,246개 모두 같았다. 따라서 특정 커널이나 전송 방식의 문제라고 단정하지 않는다.

## 한자 혼입

현재 temperature 0.7 / top_p 0.95 / top_k 20 / presence_penalty 0과 top_p 0.8, 한국어 안내문, 더 낮은 temperature를 비교했다.

- 비추론 12회씩: 현재 한자 포함 5/12, top_p 0.8은 6/12, 약한 안내문은 5/12.
- 강한 안내문 8회씩: 현재 4/8, 안내문 2/8, 안내문+top_p 0.8은 4/8, 안내문+temperature 0.5/top_p 0.8은 3/8. 작은 표본에서 효과가 일관되지 않았다.
- xhigh 새 대화 4회 중 출력 한도 8192 내 완결은 1회였다. 빈 답변·잘린 답변을 한자 억제 성공으로 세지 않았다.
- 실제 문제가 있던 대화의 텍스트만 재생한 4회는 양쪽 모두 한자가 없어 원래 현상을 재현하지 못했다. 도구 정의·회상은 빠진 재생이므로 실제 요청 전체와 동일하지 않다.
- 중국어 인용·한자 표기·영어·JSON을 명시적으로 요청하는 호환성 검사는 통과했다.

**자동 안내문과 샘플링 변경은 적용하지 않는다. 한자 혼입은 해결되지 않았다.** 개인 대화·페르소나 원문은 실험 결과에 저장하지 않았으며 재생 결과는 해시·문자 수·시간만 남겼다.

## 최종 반영·검증

Compose와 Talk 내장 TP2 레시피에 `sm121-tp2-vocab-v1`, ko64k, chunk 1024를 반영했다. Talk를 다시 빌드·재시작했고 API 상태를 확인했다. TP1과 한자 혼입 관련 샘플링·페르소나는 변경하지 않았다.

- 재기동 후 임의 문자열 검색 12/12 통과.
- 정확히 1,046,528토큰 입력의 세 위치 값 3/3 회수. TTFT **1,093.57초 (18분 14초)**, 입력/TTFT 약 957 tok/s. 캐시 적중 0, 재처리 0, 입력 절단 없음.
- 이 긴 입력은 용량·검색 기능 검사다. 기존 다른 체크포인트의 1M 수치와 정밀한 속도 A/B 비교로 취급하지 않는다.
- 전체 실험의 최소 호스트 가용 메모리: 헤드 35.72GiB / 워커 42.51GiB. 최종 컨테이너 cgroup peak는 헤드 64.94GiB / 워커 73.30GiB였으며, 이는 GPU 통합 메모리 전체 점유량과 동일하지 않다. 양쪽 OOMKilled=false, watchdog 종료 기록 없음.
- Talk orchestrator/config Go 테스트, Python launch 테스트, TP2 참조 검사 통과. 최종 이미지·실험 helper·정식 helper의 SHA-256 일치.
