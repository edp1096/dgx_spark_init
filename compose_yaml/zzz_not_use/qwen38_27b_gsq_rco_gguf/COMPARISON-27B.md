# 2026-09-08 · Qwen3.8 27B 실행 구성 비교

새 GGUF는 **EXL3+MTP와 비슷한 생성 속도**를 냈다. 프롬프트 캐시를 1GiB로
제한하면 실행 후 추가 메모리가 약 **17.3GiB**로 줄었고 이미지 입력도 동작했다.
다만 사실성 우위는 확인되지 않았다. 같은 원본의 BF16이 맞힌 직접 사실 질문에서
GGUF는 사망 연도를 틀렸다.

## 주요 결과

속도는 API가 보고한 출력 토큰 수를 클라이언트 왕복 시간으로 나눈 값이다.
입력 처리와 API 오버헤드를 포함한다. 메모리는 아래 설명한 호스트 가용 메모리
감소량이며, 순수 가중치 메모리나 최대 사용량이 아니다.

| 구성 | 전체 tok/s | 추가 메모리: 기동 직후 → 검사 후 | 첫 응답 중앙값 | 이미지 API |
|---|---:|---:|---:|---|
| NVFP4 + DFlash2, 초안 8토큰 | 22.29 | 34.8 → 36.1GiB | 0.231초 | 색상 검사 통과 |
| EXL3 4bpw + MTP | 24.95 | 19.1 → 20.3GiB | 0.531초 | 현재 어댑터 미지원 |
| 새 GGUF + MTP 3, 기본 캐시 8GiB | 24.72 | 15.7 → 20.7GiB | 0.301초 | 색상 검사 통과 |
| 새 GGUF + MTP 3, 캐시 1GiB | 24.80 | 15.7 → 17.3GiB | 0.428초 | 색상 검사 통과 |

EXL3와 GGUF의 평균 차이는 작아 속도 우열을 확정할 근거가 부족하다. 특히 EXL3
API의 토큰 집계 차이와 두 번뿐인 반복을 고려해야 한다. GGUF의 캐시 제한은
이 실행에서 약 **3.44GiB**를 절약했다. 생성 속도와 연속 반복 검색 지연은
비슷했지만, 네 가지 스트리밍 입력의 첫 응답 중앙값은 0.301→0.428초로 늘었다.

추론에 필요한 가중치 파일 합계는 NVFP4 본체 **21.92GB** + DFlash2 **3.85GB**,
EXL3 **17.07GB**, GGUF **12.12GB** + 비전 projector **0.93GB**다.
변환용 BF16 원본·중간 파일·도구 이미지·캐시는 이 파일 크기에 포함하지 않는다.

## 입력별 속도와 가속 효과

각 칸은 같은 입력의 두 번 실행을 합산한 API tok/s다.

| 구성 | 영어 코드 | 영어 수학 | 한국어 기술 | 한국어 산문 | 전체 |
|---|---:|---:|---:|---:|---:|
| NVFP4 기본, speculative off | 3.62 | 3.60 | 3.62 | 3.62 | 3.61 |
| NVFP4 + DFlash2 | 37.88 | 48.43 | 20.77 | 11.87 | 22.29 |
| EXL3 기본, MTP off | 13.50 | 13.60 | 13.66 | 13.61 | 13.59 |
| EXL3 + MTP | 29.28 | 36.51 | 25.32 | 16.86 | 24.95 |
| GGUF 기본, MTP off | 13.58 | 13.59 | 13.58 | 13.58 | 13.58 |
| GGUF + MTP 3, 캐시 8GiB | 29.37 | 32.12 | 24.28 | 18.03 | 24.72 |
| GGUF + MTP 3, 캐시 1GiB | 29.65 | 32.29 | 24.29 | 18.04 | 24.80 |

기본 대비 가속 배수는 NVFP4+DFlash2 **6.17배**, EXL3+MTP **1.84배**,
GGUF+MTP 3 기본 캐시 **1.82배**였다. DFlash2는 코드·수학에서 가장 빨랐고,
한국어 산문에서는 GGUF가 가장 빨랐다. 모든 속도 요청은 `finish_reason=length`였다.

llama.cpp가 별도로 보고한 순수 decode 처리량은 GGUF 기본 **13.69**,
MTP 3 기본 캐시 **25.14**, MTP 3 캐시 1GiB **25.31 tok/s**다.
위 표의 API 처리량과 혼용하지 않는다. 나머지 두 API는 같은 형식의
요청별 순수 decode 시간을 반환하지 않아 공통 순위에는 API 측정값을 사용했다.

## 긴 입력과 캐시 재사용

6,224토큰의 한국어 물류 기록 중간에 넣은 비밀 코드를 찾아 답하게 했다.
각 응답은 8토큰이었다. 아래 값에는 입력 처리와 답변 생성이 모두 포함된다.

| 구성 | 첫 요청 | 동일 입력 재요청 | 결과 |
|---|---:|---:|---|
| NVFP4 기본 | 5.65초 | 2.32초 | 정확 |
| NVFP4 + DFlash2 | 3.84초 | 0.49초 | 정확 |
| EXL3 기본 | 11.34초 | 1.05초 | 정확 |
| EXL3 + MTP | 11.27초 | 0.65초 | 정확 |
| GGUF 기본 | 9.99초 | 0.68초 | 정확 |
| GGUF + MTP 3, 캐시 8GiB | 10.14초 | 0.39초 | 정확 |
| GGUF + MTP 3, 캐시 1GiB | 10.08초 | 0.40초 | 정확 |

긴 입력의 첫 처리에서는 NVFP4+DFlash2가 유리했다. GGUF의 캐시 1GiB 결과는
이 6,224토큰 연속 재요청에 대한 검증이다. 여러 대화 사이의 캐시 유지나
전체 32K 입력의 반복 처리 성능까지 검증한 결과는 아니다.

## 소규모 기능·정확성 검사

BF16은 새 GGUF를 만든 **동일 Huihui 원본의 BF16 GGUF**이며, 가중치 정밀도
대조용으로만 실행했다. 같은 llama.cpp, 32K 문맥, Q8 KV, thinking off,
greedy 조건을 사용했다. BF16의 속도 순위는 측정하지 않았다.

| 검사 | NVFP4+DFlash2 | EXL3+MTP | GGUF+MTP 3 두 캐시 구성 | BF16 대조 |
|---|---|---|---|---|
| 한국어 사과 계산 | 16개, 통과 | 통과 | 통과 | 통과 |
| 구간 병합 코드 실행 | 7개 사례 통과 | 통과 | 통과 | 통과 |
| HWP 도구명·한국어 인자 | 통과 | 통과 | 통과 | 통과 |
| 도구가 필요 없는 인사 | 통과 | 통과 | 통과 | 통과 |
| 이미지 좌우 색상 | 통과 | API 미지원 | 통과 | 통과 |
| 긴 입력의 비밀 코드 | 통과 | 통과 | 통과 | 통과 |
| 분수만 답하기, 64토큰 한도 | 지시 불이행 | 지시 불이행 | 지시 불이행 | 지시 불이행 |
| 직접 역사 질문의 세 사실 | 계기 인물 오답 | 계기 인물 오답 | 덩샤오핑 사망 연도 오답 | 세 사실 모두 정답 |

코드는 입력 비변경을 포함해 빈 입력, 중첩, 경계가 닿는 구간, 음수, 중복,
단일점, 서로 떨어진 구간을 실행 검사했다. 실행 환경은 네트워크·호스트 마운트·
GPU가 없는 일회용 컨테이너다. EXL3 도구 인자의 `\u…` 표기는 정상 JSON
이스케이프이며, 실제 디코딩 후 한국어 제목과 본문이 정확했다.

EXL3의 현재 `serve_openai.py`는 토큰화한 텍스트 ID만 생성기에 전달하며
이미지 전처리·임베딩 경로가 없다. 실제 색상 답변도 `white/white`였다.
이는 **설치된 API 어댑터의 한계**다. EXL3 가중치에는 비전 타워가 있으므로
모델 형식 자체가 이미지를 지원할 수 없다는 뜻은 아니다.

수학 검사는 모든 구성에서 설명을 시작하다 64토큰 한도에 도달했다.
따라서 확인된 실패는 “분수만 답하라”는 지시 준수이며, 이 검사만으로
계산 능력이 없거나 최종 계산값을 틀렸다고 판정하지 않는다.

### 사실 오류와 BF16 대조

직접 질문의 정답은 후야오방, 1989년, 덩샤오핑 1997년이다.
후야오방은 전 중국공산당 총서기이며 국가주석이 아니었다.
[후야오방과 시위의 계기](https://time.com/3908456/tiananmen-massacre-china-chengdu-june-4-1989/),
[덩샤오핑 사망 공식 발표](https://www.scmp.com/article/185622/official-announcement-issued-241-am).

- **NVFP4 기본:** 장문에서 호치민이 사망했다고 썼다. 직접 질문에서는
  계기 인물을 “훙웨이”, 후야오방의 사망 연도를 1999년으로 답했다.
- **NVFP4+DFlash2:** 장문에서 후야오방을 국가주석으로 잘못 불렀다.
  직접 질문은 “훙웨이차오”라는 잘못된 인물과 올바른 두 사망 연도를 출력했다.
- **EXL3 기본:** 장문에서 덩샤오핑이 1989년 4월 5일에 사망했다고 썼다.
  기본·MTP 모두 직접 질문에서 시위 계기가 된 특정 사망자는 없다고 답했다.
  두 사망 연도는 맞혔다.
- **GGUF 기본:** 장문에서 `허룽(胡耀邦)`으로 이름을 잘못 표기했다.
  MTP 3 두 구성에서는 이전 MTP 2 검사에서 발견했던 “덩샤오핑이 1989년에
  사망했다”는 오류가 재현됐다. 세 GGUF 구성의 직접 답변은 후야오방·1989년·
  덩샤오핑 **2009년**으로 같았다.
- **BF16:** 직접 질문의 세 사실은 모두 맞혔다. 원래 장문 질문에서는
  계기 인물을 언급하지 않았으며, 독일 통일을 1989년의 시위 배경에 포함하는
  다른 연대 오류가 있었다. 독일 통일은 1990년 10월 3일이다.
  [독일 연방정부 연표](https://www.bundesregierung.de/breg-de/schwerpunkte/deutsche-einheit/die-einheit-ist-wirklichkeit-432814).

직접 질문에서는 같은 원본의 BF16 대비 IQ3 GGUF의 정확도 저하가 관찰됐다.
동시에 다른 양자화 구성과 BF16 장문에도 오류가 있어, 모든 사실 오류를
IQ3 양자화 하나의 탓으로 돌릴 수는 없다. 이 소규모 검사로 일반적인
지능 순위나 무손실 양자화를 주장하지 않는다.

## 조건과 해석 범위

- DGX Spark 한 대, GPU 서버 하나씩 순차 실행. 비교 전후 GPU 모델은 모두
  정지 상태다. 기존 문서 서비스는 계속 실행했다.
- 문맥 한도 32,768, 요청 동시성 1, CPU affinity `5-9,15-19`.
- 속도 입력 4개 × 2회: 최대 512토큰, temperature 0.6, top-p 0.95,
  top-k 20, seed 42, thinking off. 같은 seed가 동일 출력을 보장하지는 않았다.
- API가 보고한 실제 출력 수는 NVFP4/GGUF 512, EXL3 기본 511,
  EXL3 MTP 507이었다. 이를 그대로 합산했다. 보고 토큰 수의 정의나 집계
  차이를 별도 보정하지 않았으므로 1% 안팎의 순위 차이를 과해석하면 안 된다.
- 첫 응답은 속도 반복 이후 각 입력을 128토큰 한도로 스트리밍한 결과다.
  캐시가 남아 있을 수 있는 warm 지연이며, EXL3의 16자 출력 보관도 포함한다.
- 기능 검사는 temperature 0. 총 8개 구성에서 속도 응답 56개,
  스트리밍 응답 28개, 기능 응답 80개를 저장했다. BF16은 기능 검사만 수행했다.
- KV 형식은 SGLang FP8, EXL3 NVFP4, llama.cpp Q8이다. 원본도
  EXL3는 `orcarouter/Qwen3.8-27B-Uncensored`, GGUF는 Huihui로 다르다.
  **실행 구성 비교이며 동일 가중치에 적용한 양자화 알고리즘 비교가 아니다.**
- NVFP4는 혼합 정밀도 체크포인트다. GGUF는 기존 ISTA 배분·imatrix를
  재사용한 IQ3_S 결과이며 새 GSQ 최적화나 RCO 탐색 결과가 아니다.
- SGLang은 32K 문맥 설정만으로 약 704K 토큰의 KV를 할당해, 실제 측정에는
  `--max-total-tokens 32768`을 추가했다. 최초 무제한 준비 로그는 보존했지만
  그 실행은 측정 표에 포함하지 않았다.
- NVFP4 기본의 준비 중 FP8 변환 컴파일 오류 로그가 있었으나 이후 CUDA
  그래프 준비와 서버 기동이 완료됐다. 실행 로그에서 CUDA graph 활성화를
  확인했으며, 측정 요청은 모두 완료됐다. 설치된 런타임의 결과로 해석한다.
- 메모리는 `/proc/meminfo`의 `MemAvailable`을 기동 전·준비 후·검사 후에
  측정한 차이다. GB10 공유 메모리, 런타임 예약, 캐시와 호스트 활동이 반영된다.
  요청 중 최대값이나 프로세스별 전용 GPU 메모리 측정은 아니다.
