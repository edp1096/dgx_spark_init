# MiniMax H3 character-sheet runtime

MiniMax H3 Ref2VA를 실험용 T=1 Image VAE와 함께 사용하는 독립 ComfyUI
런타임입니다. Krea 2 서비스와 모델 캐시만 공유하며 실행 프로세스와 출력은
분리합니다.

필수 가중치는 시작 시 `media-hf-cache`에 내려받아 ComfyUI 모델 폴더에
심볼릭 링크합니다. H3 실행에 실제로 필요한 최초 준비 용량은 약 42.4 GiB입니다.
Gemma 4는 이 그래프에서 사용하지 않으므로 별도로 받지 않습니다.

```bash
docker compose up -d --build
docker logs -f minimax-h3-comfyui
```

ComfyUI는 `http://127.0.0.1:8190`, Spark Media용 로컬 API는
`http://127.0.0.1:8191`에서 열립니다. Spark Media의 캐릭터 준비 화면은 대표
이미지를 이 API에 보내 실제 124프레임 360° 회전을 만든 뒤, 실측으로 보정한
정면·¾·측면·후면 8방향 프레임을 사용자 검토용으로 받습니다. 선택한 프레임만
Gemma 보조 분석 자료가 되며 원본 ReID 대표 이미지는 자동 교체하지 않습니다.

```bash
curl -F operation_id=character-turntable-test \
  -F image=@data/input/dynamic-h3-front-square.png \
  http://127.0.0.1:8191/v1/character/turntable
```

검증 그래프는 `smoke_test.py`에 있으며 시드·입력·출력 이름과 해상도·스텝을
환경 변수로 바꿀 수 있습니다. 기본값은 원본 워크플로우와 같은 2816×2816,
8 steps, seed 1입니다.

```bash
H3_FACE_IMAGE=h3-face.png \
H3_OUTFIT_IMAGE=h3-outfit.png \
H3_OUTPUT_PREFIX=h3-smoke/test \
H3_SEED=1 H3_STEPS=8 python3 smoke_test.py
```

착용 사진을 두 번째 참조로 그대로 넣으면 그 사람의 얼굴·피부·머리와 배경도 함께
조건으로 읽힐 수 있습니다. Spark Media의 Garment Extractor가 반환하는
`reference_b64`처럼 선택한 의상 픽셀만 중립 배경에 배치한 이미지를 사용합니다.
투명 PNG는 로더에 따라 알파가 무시될 수 있으므로 H3 참조로 직접 사용하지 않습니다.
팔이나 머리카락에 가린 옷 부분은 분할만으로 복원되지 않으므로, 가림이 큰 경우에는
별도 제품 사진이나 선택적인 생성형 의상 복원이 필요합니다.

고정된 구성:

- ComfyUI: 기반 이미지의 `cc0fc21fea7a6a82f568362b15b7fbd713b419c1`
- toobusy: `v0.4.9` (`8a1f3858deaac51187b08800c5faa23ee84b63c9`)
- TorchAudio: NGC PyTorch 26.07/CUDA 13.3 ABI용 로컬 빌드

## 얼굴 보존 통제 실험

동일한 얼굴·의상 참조에 대해 왼쪽 정면 패널과 원본 얼굴의 ArcFace
`buffalo_l/w600k_r50` cosine similarity를 측정했습니다. 한 행마다 표시된 변수만
바꿨습니다.

| 조건 | 해상도 | steps | seed | 얼굴 영역 | cosine |
|---|---:|---:|---:|---:|---:|
| 검증 기준 | 2816×2816 | 8 | 1 | 220×308 | 0.894 |
| 해상도만 이전 값 | 1344×768 | 8 | 1 | 60×82 | 0.413 |
| seed만 이전 값 | 2816×2816 | 8 | 104729 | 218×307 | 0.914 |
| prompt만 이전 값 | 2816×2816 | 8 | 1 | 221×317 | 0.880 |
| steps만 증가 | 2816×2816 | 12 | 1 | 229×326 | 0.650 |

초기 저품질 얼굴의 원인은 `1344×768` 해상도입니다. 세 패널로 나뉘면서 정면 얼굴이
약 60×82 픽셀에 불과해 정체성 정보가 무너졌습니다. 이전 seed와 prompt는 원인이
아닙니다. 12 steps는 별개의 실패 요인이므로 현재 Turbo 구성에서는 검증된 8 steps를
유지합니다.

### 3면도 해상도 기준

동일 조건에서 정사각형 해상도를 단계별로 확인한 결과입니다.

| 해상도 | 정면 얼굴 영역 | cosine | 웜 생성 시간 |
|---:|---:|---:|---:|
| 1536×1536 | 122×172 | 0.765 | 50초 |
| 1792×1792 | 149×213 | 0.670 | 56초 |
| 2048×2048 | 159×226 | 0.829 | 66초 |
| 2304×2304 | 약 177~183×250~261 | 0.839~0.871 (3 seeds) | 약 68~74초 |
| 2816×2816 | 220×308 | 0.894 | 약 98초 |

3패널 캐릭터 시트의 최소 지원 해상도는 `2304×2304`, 품질 권장값은 원본
워크플로우와 같은 `2816×2816`으로 둡니다. `2048×2048` 이하는 미리보기 용도로만
간주합니다. 캔버스 높이와 각 패널 폭이 모두 얼굴 약 250px 이상을 확보해야 하므로,
3면도에서는 비정사각형 저해상도로 자동 축소하지 않습니다.
