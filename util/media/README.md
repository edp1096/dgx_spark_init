# Spark Media

이미지·LTX 영상·CustomVoice 음성 생성·자막 API를 사용하는 Go/Svelte 클라이언트입니다. 이 프로젝트에는
모델 런타임, Python 코드, Docker 제어 로직이 포함되지 않습니다.

API 서버는 별도 프로젝트로 운영합니다.

| 화면 기능 | API 위치 | 기본 주소 | 필요 여부 |
|---|---|---|---|
| 고품질 이미지 생성 | `compose_yaml/krea2_turbo_nvfp4` | `http://127.0.0.1:8691` | 이미지 생성 모드 |
| vLLM-Omni 공통 런타임 이미지 | `compose_yaml/vllm_omni` | 포트 없음 | Qwen3-TTS 이미지 최초 빌드 시 |
| 음성 생성 | `compose_yaml/qwen3_tts` | `http://127.0.0.1:8692` | 음성 탭 사용 시 |
| 음성 인식 | `compose_yaml/qwen3_asr` | `http://127.0.0.1:8694` | 자막 탭 사용 시 |
| 영상 생성 | `compose_yaml/ltx-2.5_api` | `http://127.0.0.1:8695` | 영상 탭 사용 시 |
| AI 대화·프롬프트 향상·번역 | `compose_yaml/llama.cpp` | `http://127.0.0.1:8696` | AI 제어·향상·자막 번역 사용 시 |
| 미디어 다운로드·분할 | `compose_yaml/media_access_api` | `http://127.0.0.1:8697` | URL·자막 처리 시 |
| 이미지 고화질화 | `compose_yaml/seedvr2_upscaler` | `http://127.0.0.1:8698` | 최근 이미지 후처리 시 |
| 의상 추출 | `compose_yaml/garment_extractor` | `http://127.0.0.1:8705` | 의상 투명 PNG·마스크 추출 시 |
| 얼굴 교체 | `compose_yaml/reactor_faceswap` | `http://127.0.0.1:8706` | ReActor/INSWapper 얼굴 직접 교체 시 |

Media 앱 자체는 Go 바이너리이며 Docker 컨테이너가 아니다. 모든 API는 서로
독립적이므로 사용할 탭에 필요한 것만 올릴 수 있다. 자막 탭에서 로컬 음성만
전사하려면 Qwen3-ASR과 Media Access API가 필요하고, 번역이나 AI 대화 제어까지
사용하려면 Gemma 4 12B llama.cpp 서비스도 실행한다. SparkTalk과 공유하는 이 서버는
64K text·vision 입력을 지원한다. vLLM-Omni 항목은 상시 실행하는 API가
아니라 Qwen3-TTS가 사용하는 `dgx-vllm-omni:v0.26.0` 런타임 이미지를 만드는 빌더다.

## 클라이언트 빌드

```bash
make build
make dist
```

처음 실행하면 바이너리가 있는 디렉터리에 `media.yaml`과 `data/`가 생성됩니다.
따라서 `dist/media`와 플랫폼별 배포 바이너리는 실행한 현재 디렉터리와 관계없이 항상
`dist/media.yaml`과 `dist/data/`를 사용합니다. 설정 위치를 별도로 고정하려면
`SPARKMEDIA_CONFIG_PATH`에 설정 파일의 경로를 지정할 수 있습니다. 기본 주소는
`http://0.0.0.0:8686`입니다. `media.yaml`에는 독립 API 서버의 endpoint만 지정합니다.

```yaml
engines:
  image:
    endpoint: http://127.0.0.1:8691
  speech:
    endpoint: http://127.0.0.1:8692
  recognition:
    endpoint: http://127.0.0.1:8694
  video:
    endpoint: http://127.0.0.1:8695
  prompt:
    endpoint: http://127.0.0.1:8696
  media:
    endpoint: http://127.0.0.1:8697
  upscale:
    endpoint: http://127.0.0.1:8698
  trainer:
    endpoint: http://127.0.0.1:8704
  garment:
    endpoint: http://127.0.0.1:8705
  faceswap:
    endpoint: http://127.0.0.1:8706

image:
  default_mode: create
  default_checkpoint: official-int8
  visible_checkpoints: [official-int8, official, chriscole-edit-v1.1, moody-v7]
  backends:
    create:
      endpoint: http://127.0.0.1:8691
      model: krea2-turbo-nvfp4
```

클라이언트를 종료해도 API 서버는 영향을 받지 않습니다. 헤더에는 필요한 API 전체의
상태가 하나의 신호등으로 표시되며, 이를 누르면 API별 `online`·`offline` 상태를
확인할 수 있습니다.

생성 이미지 목록의 `얼굴` 또는 상단 `얼굴 교체`를 누르면 대상 이미지와 가져올 얼굴을
파일·생성 결과·URL에서 각각 고를 수 있습니다. 얼굴 교체는 Krea Identity Edit로 다시
그리는 작업이 아니라 ReActor의 `inswapper_128.onnx`가 얼굴 영역을 직접 합성하는 독립
작업이며 결과와 두 입력은 재시도를 위해 작업 기록에 보관됩니다. ReActor 코드는 GPL-3.0,
InsightFace 사전학습 가중치는 비상업 연구용 조건이므로 배포·상업 이용 전 별도 확인이 필요합니다.

이미지 탭의 `Krea 2 Turbo`는 ComfyUI 그래프를 노출하지 않고 기능 모듈을 켜고 끄는
제어판으로 구성됩니다. `인물·장면 유지`는 Krea Identity Edit, `자세·구도`는 Krea
Depth Control, `스타일 LoRA`는 선택한 Krea LoRA들을 개별 강도로 순차 중첩하며 세
모듈은 동시에 사용할 수 있습니다. 선택한 LoRA와 강도는 작업 기록에 저장되어 설정
복제로 그대로 복원됩니다. 두 장 Identity 편집에서는 주 참조에 장면, 추가 참조에 삽입할 인물을
넣습니다. 의상·포즈 참조는 Identity Edit v1.2.3과 네이티브 `ImageStitch`를 사용합니다.

`원본 수정 → 머리 전체 교체`는 일반 Identity Edit 대신
[`BFS Head Swap V1.1`](https://huggingface.co/Alissonerdx/BFS-Best-Face-Swap)을
공식 Krea 2 INT8 ConvRot 그래프에 적용합니다. 얼굴뿐 아니라 머리카락과 두상까지
교체하지만, 참조 사진에 의상이 크게 보이면 그 의상도 결과에 섞일 수 있으므로 머리
중심의 근접 사진이나 미리 잘라낸 투명 PNG를 사용하는 것이 좋습니다.
생성 설정의 체크포인트 목록에서는 검증된 `Identity 전용 · ConvRot INT8` 또는 현재
선택 체크포인트를 고르고, 같은 줄의 텍스트 인코더에서는 `Heretic INT8 ConvRot`과 기본
Qwen3-VL FP8을 비교 선택할 수 있습니다. `실험 편집·윤곽`은 NK2E v0.3의 국소 편집 또는 Canny 구조 참조를 사용하며,
현재는 다른 Krea 모듈과 조합하지 않습니다. `부분 수정·확장`은 Krea2 AnyPaint로 흰색
마스크 영역을 다시 그리거나 원본의 상·하·좌·우 캔버스를 확장합니다. 마스크가 없으면
아웃페인트만 수행하며, 프롬프트에는 변경 지시보다 완성될 전체 장면을 적는 편이
안정적입니다. 원본 위에서 브러시·지우개로 직접 수정 영역을 칠하거나, 반투명 인물·얼굴·
가로·사각 프리셋을 이동하고 크기를 조절해 마스크로 만들 수 있습니다. 외부에서 만든
흑백 마스크 파일도 계속 사용할 수 있습니다. 원본과 마스크는 작업 기록에 보관되어
`참조` 또는 `전체 작업` 복제로 재사용할 수 있습니다. 모든 기능 모듈의 입력 썸네일과
최근 생성 결과는 클릭하면 공통 확대 모달로 열립니다. 과거 Klein 작업 기록을 전체 복제하면 참조 이미지를
Krea Identity 입력으로 변환합니다.

`다중 장면`은 2~12개의 스토리보드·삽화를 한 번에 이미지 큐에 넣습니다. 이야기나 주제를
Gemma가 지정한 수의 장면으로 나누거나 각 장면을 직접 작성할 수 있으며, 생성 전에 인물·세계관·
화풍을 한국어 공통 설정으로 정리하고 각 장면을 완결된 독립 Text-to-Image 프롬프트로 만듭니다.
공통 설정은 사용자가 한국어로 수정할 수 있습니다. 서버는 캐릭터별 영어 외형 블록을 한 번 확정한
뒤 등장하는 모든 장면에 같은 문구를 그대로 삽입하므로 장면마다 외형을 다시 번역하거나 요약하지 않습니다.
첫 번째 캐릭터에서 사용자가 `대표 · ReID`로 고른 이미지는 공식 체크포인트에서 Krea2 ReID 앵커로
모든 장면에 전달됩니다. 나머지 참조는 Gemma 외형 분석 자료로만 사용합니다. `캐릭터 준비`에서
얼굴·머리·체형·의상·액세서리·기계 구조 중 장면마다 고정할 특징을 고른 뒤, Gemma가 만든 영어 외형
문구를 사용자가 검토·수정할 수 있습니다. 사람 얼굴·머리·체형의 독립 장면 일관성은 크게 좋아지지만
대표 이미지의 의상이나 액세서리가 ReID를 통해 함께 고정될 수 있고,
로봇·갑옷처럼 부품 구조가 중요한 대상은 세부 형상까지 동일하게 보장하지 않습니다. 나머지 캐릭터는
현재 확정된 영어 외형 블록으로 유지합니다. 선택적인 QuadView 후보는 원본과 나란히 검토하여 승인한
경우에만 Gemma 보조 분석 자료로 추가하고 ReID 대표 이미지를 자동 교체하지 않습니다. 전체 묶음을
생성하기 전 `3장 시험`으로 얼굴·복장·소품의 실제 유지 정도를 확인할 수 있습니다. 모든
장면은 같은 체크포인트·해상도·스타일 LoRA·사용자 LoRA를 공유하지만 직전 결과를 다시 편집하지
않으므로 오류가 다음 장면으로 누적되지 않습니다. 결과는 생성 이미지 목록에 `장면 n/N`으로
표시됩니다. 영상 시작·끝·키프레임에는 필요한 결과를 직접 선택할 수 있지만, 다중 장면 자체는
영상 프레임의 시간적 연속성을 보장하지 않습니다. Depth·Vision·NK2E·AnyPaint·사용자 Identity
입력은 다중 장면과 동시에 사용하지 않습니다.

ReID 회귀 검증은 `scripts/krea_reid_diversity_validation.py`로 수행할 수 있습니다. 남자 노인,
젊은 흑인 남성, 거친 중년 남성, 서양 여성, 동양 여성의 상세 기준 얼굴을 만든 뒤, 인물 외형을 전혀
쓰지 않은 짧은 시장·해변 장면 프롬프트로 ReID 결과와 동일 시드의 비-ReID 대조군을 비교합니다.

이미지 작업이 대기·실행 중이면 최근 이미지 카드에 경과 시간, 예상 진행률, 남은 시간과
예상 완료 시각을 표시합니다. ETA는 동일한 모드·해상도·스텝의 최근 완료 시간 중앙값을
우선 사용하며, 실제 ComfyUI 스텝 이벤트가 아닌 추정치임을 화면에 명시합니다. 앱 재시작이나
엔진 오류로 실패한 이미지 작업은 저장된 프롬프트·설정·참조 파일을 사용해 `재시도`할 수
있습니다. 확산 중간 latent는 보존하지 않으므로 실패 지점이 아닌 처음부터
다시 실행하며, 시드가 `-1`이었던 작업은 새로운 무작위 결과가 나옵니다.
이미지·영상·음성 생성과 이미지 후처리는 통합 FIFO 큐에 저장되어 순차 실행됩니다.
브라우저를 닫아도 대기 작업은 유지되고, 한 작업이 실패해도 다음 작업으로 넘어갑니다.
대기 작업은 카드에서 취소할 수 있으며 앱 재시작 뒤에도 대기열이 복구됩니다. 재시작 시
이미 실행 중이던 원격 생성 요청만 중복 실행 방지를 위해 실패 처리한 뒤 재시도할 수 있습니다.

Identity에는 얼굴·특징에 주의를 집중하는 마스크와 변경을 허용할 영역만 지정하는
수정 한정 마스크를 별도로 사용할 수 있습니다. `내용·구도 참조`는 Qwen3-VL
conditioning으로 최대 4장의 내용을 참고하고, `스타일 이미지 참조`는 최대 2장에서
화풍·색감·질감을 가져옵니다. 파일·최근 결과·프리셋을 제공하는 각 이미지 입력에는
`URL` 가져오기도 있으며, 서버가 PNG·JPEG·WebP·GIF를 최대 32MB까지 내려받아 일반
업로드와 동일하게 처리합니다. 인식 가능한 입력 이미지는 픽셀과 알파를 보존하는 PNG로
저장하고, URL 요청도 가능한 경우 원본 PNG·JPEG를 WebP보다 우선합니다. 전용 모델을 사용하는 기능은 화면에서 호환되지 않는
다른 모듈과의 동시 선택을 제한합니다. 모델 내부 조정에서는 프롬프트 준수 강화와
2-vector·3-vector 필터 완화 가중치를 선택하고 강도를 조절할 수 있습니다. 별도 `생성
설정`에서는 시드·스텝과 기본 `Euler/Simple` 또는 디테일 탐색용 `ER-SDE/Simple`
프리셋을 고릅니다. 실제 무작위 시드·샘플러·스케줄러·스텝은 작업 기록과 이미지 EXIF에
함께 저장됩니다.

이미지 프롬프트 향상을 켜면 Gemma 4 12B가 Krea 2용 영어 프롬프트를 제안합니다.
`프롬프트 향상`으로 결과를 먼저 확인하거나 `향상 및 생성 시작`으로 한 번에 진행할 수 있습니다. JSON처럼 구조화된 프롬프트는
임의로 변경하지 않습니다. 이미지 크기는 화면 비율과 0.75/1/2MP 등급만 고르는 간편 모드가
기본이며, 필요한 경우 폭과 높이를 직접 지정할 수 있습니다. 최근 이미지의 `고화질로 만들기`는
별도 SeedVR2 3B FP8 서비스로 2배 복원한 결과를 새 이미지 작업으로 보존합니다.
생성 영상과 받아쓰기의 영상 원본도 `고해상도`에서 SeedVR2로 1.01~4배 복원할 수 있습니다. FHD 1920×1088·2K/QHD 2560×1408·4K 3840×2176 LTX 정렬 상자 안에 원본 비율을 유지해 맞추며 세로 영상은 목표 상자를 자동으로 회전합니다.
결과는 원본을 덮어쓰지 않고 새 영상 작업으로 저장됩니다. 60초를 넘는 원본은 통합 메모리를
보호하기 위해 시작·끝 시간을 지정한 최대 60초 구간으로 처리합니다.

원본 수정의 `인물 교체·의상 적용`에서 사용자가 프롬프트를 비우면 로컬 Gemma 4
비전 모델이 원본의 대명사와 의상 참조의 색상·재질·의류명만 짧게 추출합니다. 서버는
이를 `she is now wearing the ...` 및 포즈 참조가 있으면 `she now holds the same
pose.` 형태의 짧은 줄로 조립합니다. 사용자가 직접 쓴 편집 지시는 일반 생성용
`Change/Preserve` 설명문으로 감싸지 않고 그대로 Krea Identity Edit에 전달합니다.
사용자가 추가 변경을 입력하면 Gemma에는 현재 Identity 작업 종류와 보존 선택을 내부
컨텍스트로 전달합니다. 최종 Krea 지시는 의상 교체와 추가 변경을 한 문장으로 합치고,
포즈 참조가 있으면 두 번째 짧은 문장으로 제한해 일반 T2I용 장문 향상을 피합니다.

프롬프트 예제 모달에는 Krea 공식 예제를 우선 표시하고 각 예제의 출처를 함께
제공합니다. 우상단 `랜덤`은 공개된 `Crocody/mymuse`의 `muse(no_camera).txt` 장면
20,101개 중 하나와 `Style.txt` 촬영 스타일 17개 중 하나를 무작위로 조합해 이미지
프롬프트를 바로 교체합니다. 고정된 Sony A7R·85mm 문구가 들어 있는 `muse.txt` 대신
카메라 문구를 덜어낸 변형을 사용하므로 휴대폰 스냅·직광·필름·스튜디오 등 실제 촬영
성격은 선택된 Style이 결정합니다. 원본 텍스트는 최초 준비 후
`data/prompt-wildcards/crocody-mymuse/`에 보관되어 이후에는 인터넷 없이 사용합니다.
영상 탭에서 예제를 열면 이미지용 Krea 예제 대신 LTX 전용 영상 프롬프트가
표시됩니다. Lightricks 공식 `LTX-Video` 저장소의 Apache-2.0 작성법과
출처를 우선 표시하며, LTX 블로그·Hugging Face 토론·MaxVideoAI·Replicate·
RunDiffusion은 원문 프롬프트를 복제하지 않고 촬영 구성 원칙만 참고해 새로 작성한
예제와 출처 링크를 제공합니다.
영상 예제의 `랜덤 영상`은 장면 이미지가 없을 때 `muse(no_camera)` 장면과 Style을
고른 다음, 현재 영상 길이 안에서 실행 가능한 단일 원테이크의 피사체 동작·카메라
이동·환경 움직임·음향을 Gemma 4가 추가합니다. 변환 결과는 즉시 덮어쓰지 않고
상세 화면에서 확인한 후 `이어서 적용`·`새로 적용`을 고릅니다.
같은 도구 모음의 `Portrait Lab`은 PORTRAIT LAB v1.7.1 원본 단일 HTML을 새 탭에서
엽니다. 원본은 수정하지 않고 Spark Media 복귀·버전·출처만 제공하는 로컬 래퍼 안에
표시합니다. 버전이 고정된 ZIP과 HTML은 SHA256을 검증한 뒤
`data/tools/portrait-lab/v1.7.1/`에 보존되며, 앱을 다시 설치했을 때도 최초 한 번만
다운로드합니다.
우하단 번개 버튼은 로컬 Gemma 4 12B와 대화해 탭 이동, 생성 설정,
Krea 기능 모듈 열기와 작업 준비를 수행합니다. 실제 생성·음성·자막 요청은 대화창의
확인 버튼을 한 번 더 눌러야 실행됩니다. 이미지 내용을 찾거나 비교하는 질문에는 현재
페이지의 완료 이미지 최대 12장을 번호가 표시된 3열 연락처 시트로 합성해 Gemma 4
mmproj에 한 번만 전달하며, 일반 설정 명령은 텍스트 경로를 유지합니다. 프롬프트 조립기에서는 주제·외형·포즈·카메라·환경·조명·재질·스타일·
글자·유지 조건을 조합할 수 있으며, 포즈 120개와 메이크업·얼굴 연출 프리셋을
미리보기로 선택할 수 있습니다. 조립 결과는 모달 하단에 고정되며 현재 프롬프트를
교체하거나 뒤에 이어 붙일 수 있습니다.

`LoRA` 탭은 학습기가 아니라 모델 관리 화면입니다. Civitai 주소·모델 버전 ID 또는
Hugging Face 모델/파일 주소를 입력해 LoRA를 내려받고 표시 이름·트리거·기본 강도를
수정하거나 삭제할 수 있습니다. Civitai API 키와 Hugging Face read 토큰은 `설정 → 연결 → 다운로드 인증`에서
한 번 저장해 Krea 체크포인트·LoRA·LTX 다운로드가 함께 재사용하며 화면으로 다시 전송하지 않습니다. 등록된 LoRA는 이미지 탭의 `사용자 LoRA`
모듈에서 최대 5개를 각기 다른 강도로 중첩할 수 있습니다. LoRA 학습은 별도 공식
Ostris AI Toolkit 컨테이너에서 진행하며, `LoRA` 탭의 `Ostris 열기`로 현재 호스트의
8675 포트를 새 탭에서 엽니다.

이미지·영상·음성·자막의 최근 결과와 전체 생성 기록은 페이지 단위로 표시됩니다.
탭마다 표시 개수와 최신순·오래된순 정렬을 독립적으로 저장하며, 상단과 하단에서
페이지를 이동할 수 있습니다. 이미지·영상·자막은 갤러리와 목록 보기를 지원하고
결과를 모달에서 크게 열 수 있습니다. 이미지 모달에서는 원본 파일과 생성 설정이
담긴 EXIF 정보를 확인할 수 있습니다.

이미지 생성 도구 모음과 각 생성 이미지의 `의상` 후처리에서는 직접 업로드·URL·생성
결과를 원본으로 선택해 의상을 투명 PNG와 흑백 마스크로 분리합니다. 같은 의상의 보완
사진을 최대 4장 추가하면 사진별 의상 면적·잘림·선명도를 비교해 가장 좋은 실제 원본을
자동 선택합니다. 여러 시점에서 보이지 않는 부분을 임의로 합성하지 않으므로, 가림이
적고 옷 전체가 보이는 사진을 보완 이미지로 넣는 것이 좋습니다. 분할 모델은 revision을
고정한 `fashn-ai/fashn-human-parser`이며 별도 API 컨테이너에서 실행됩니다.

화면의 `설정` 탭은 `연결`, `기본값`, `이미지 정보`, `저장소`로 구분됩니다. 각 API
endpoint와 모델·해상도·언어·업로드 제한 등의 기본값을 수정하고, 새 이미지 EXIF에
기록할 제작자·저작권·설명을 관리할 수 있습니다. 저장한 연결 정보와 기본값은 즉시
적용되고 `media.yaml`에도 기록됩니다. `listen`과 `data_dir` 변경만 Media 프로세스를
다시 시작해야 적용됩니다.

`연결`의 `Krea 체크포인트 준비`에서는 Civitai API 키를 한 번 입력해 Ray Artshoot
V1 FP8·V2 FP8·V3 INT8·V4 INT8과 Moody V7·Cutie V4·Amateur V1 NVFP4를 선택
다운로드합니다. 키는 모델 캐시 볼륨에
권한 제한 파일로 저장되고 화면이나 설정 YAML로 다시 노출되지 않습니다. 준비된 모델은
이미지 생성 화면과 `생성 기본값 → 이미지`에서 선택하며 작업 기록과 재시도에도 유지됩니다.
외부 모델은 필터 조정이 이미 병합돼 외부 필터 완화를 자동으로 끕니다. Moody 모델을
선택하면 제작자 권장 `Euler Ancestral + Beta` 샘플링 프리셋이 자동 적용됩니다.
같은 화면에서 V2·V4 BF16을 받아 GB10 네이티브 NVFP4로 변환할 수 있습니다. 변환본은
파일 구조 검사와 실제 이미지 생성 검증을 모두 통과해야 선택 가능하며, BF16 원본 삭제는
검증 성공 후에만 적용되는 선택 사항입니다. V1~V4 제공본의 스타일 LoRA·Depth·Identity
Edit·AnyPaint 호환성은 각각 실제 생성으로 확인했습니다.

`연결`의 `LTX 영상 모델 준비`에서는 Hugging Face read 토큰을 한 번 입력해 백지
설치의 공식 LTX 모델과 공개 Motion LoRA를 자동으로 준비합니다. SSH·수동 파일 편집이나
Compose 재시작은 필요하지 않습니다. Motion LoRA 사용 여부와 강도는 `생성 기본값 → 영상`에서
관리하며 다음 영상 작업부터 적용됩니다.

## API 서버 실행

아래 명령은 모든 탭을 사용할 때의 전체 구성이다. 일부 탭만 사용한다면 위 표에
해당하는 서비스만 실행하면 된다.

```bash
docker volume create media-hf-cache
docker volume create media-krea-user-loras

cd ../../compose_yaml/krea2_turbo_nvfp4
docker compose up -d

cd ../krea2_lora_trainer
docker compose build
docker compose up -d

# Qwen3-TTS가 사용할 vLLM-Omni 런타임 이미지를 최초 한 번 빌드한다.
cd ../vllm_omni
docker compose --profile check build

cd ../qwen3_tts
docker compose up -d custom

cd ../qwen3_asr
docker compose up -d

cd ../ltx-2.5_api
docker compose up -d

cd ../seedvr2_upscaler
docker compose build
docker compose up -d

cd ../garment_extractor
docker compose build
docker compose up -d

systemctl --user start llama-cpp-spark.service

cd ../../compose_yaml/media_access_api
docker compose build
docker compose up -d
```

API 서버들은 모델 캐시 볼륨만 공유하며 서로 독립적으로 시작·종료할 수 있습니다.
Qwen3-TTS는 vLLM-Omni 런타임에서 프리셋 화자를 사용하는 CustomVoice만 운영합니다.
Qwen3-ASR은 Gradio와 vLLM 없이 공식 `qwen-asr` Transformers wrapper 및
Forced Aligner로 운영합니다.
LTX 2.5 영상 API는 일반 생성에 공식 distilled NVFP4 파이프라인을 사용하며 동시 생성은 한 작업으로 제한합니다.
음성 결과의 `A2V`는 공식 dev 체크포인트를 FP8로 로드하고 distilled LoRA를 사용하는 2단계 오디오 구동 영상으로 연결합니다.
완료 음성은 최대 8개까지 타임라인에 배치할 수 있고, 각 시작 시각 사이의 빈 구간은 무음 패딩으로 합성됩니다.
영상 탭에서는 시작·마지막 이미지와 최대 8개의 중간 키프레임을 한 줄 타임라인에서 드래그하고 시간·강도를 함께 지정할
수 있습니다. 각 장면 이미지는 파일, URL 또는 이미지 탭의 최근 결과에서 가져옵니다.
Gemma 4 12B Q4_K_M + Q8 MTP 3 llama.cpp은 LTX 캡션 형식으로 한국어 원문을
번역·확장하며 SparkTalk과 같은 64K 멀티모달 backend를 공유합니다. 프롬프트 향상이
켜져 있으면 생성 버튼 한 번으로 향상 후 바로 영상을 만들며, 시작 이미지는 LTX와 vision
prompt enhancer에 전달됩니다. 메모리 실측과 엔진 변환 방법은
`compose_yaml/llama.cpp/README.md`에 기록합니다.

자막 탭은 로컬 영상·음성 파일을 디스크로 스트리밍 업로드하거나 URL에서 미디어를
가져옵니다. Media Access API가 yt-dlp, FFmpeg, Playwright를 담당하고 영상과 음성 입력은
기본적으로 `${HOME}/.local/share/media-access-api/media`에 영구 보관하여 웹에서 Range 스트리밍합니다.
Go 앱은 미디어 자산 ID와 종류만 기록하고 Media Access API의 스트림을 프록시합니다. Qwen3-ASR은
최대 180초 WAV 구간만 받습니다. Forced Aligner가 반환한 어절 시각에 각 구간의
원본 오프셋을 더해 실제 영상 시간축의 자막 큐를 만듭니다. 결과는 SRT, VTT,
타임코드 TXT, 일반 TXT 중에서 복수 선택할
수 있으며 Gemma 4 12B 번역문 또는 원문·번역문 병기도 선택할 수 있습니다. 영상
결과에는 플레이어용 VTT가 자동 생성되고, 음성 전용 결과는 오디오 플레이어로
재생할 수 있습니다. 완료 결과의 `자막 재생성`에서는 저장된 큐를 재사용해 음성 인식 없이
원문만·번역문만·원문과 번역문 표시 및 출력 형식을 다시 선택할 수 있습니다. 작업 삭제 시 원본 미디어와 자막도 함께 삭제됩니다.
URL 작업은 영상 다운로드 바이트·퍼센트·ETA, MP4 저장, 음성 분리, ASR 구간,
번역 배치, 자막 파일 생성 단계를 각각 화면에 표시합니다. 진행 중인 자막 카드의
`중지`를 누르면 해당 작업만 `cancelled`로 전환하고 Media Access API에서 그 요청에
속한 yt-dlp 또는 FFmpeg 프로세스를 종료합니다. 중지된 작업은 삭제할 수 있으며,
남은 부분 파일은 설정의 `찌꺼기 정리` 대상입니다.

언어의 `Auto · 단일 언어`는 첫 구간에서 감지한 언어를 이후 구간에 고정하여 일반
영상의 인식 흔들림을 줄입니다. `Auto · 다중 언어`는 구간마다 자동 감지를 유지하고
감지된 언어를 모두 기록합니다. 한국어·일본어·영어가 섞인 노래처럼 실제 후렴이
반복되는 입력에서는 반복 문장을 ASR 환각으로 간주하지 않되, 잘못된 타임스탬프와
한 시점으로 뭉친 정렬 결과는 계속 거부합니다.

영상 링크는 `영상 내부 선택지 조회`로 사이트가 제공하는 선택지를 먼저 불러올 수
있습니다. SupJav의 숫자 버튼은 파트로, 각 파트의 버튼은 영상 출처로 표시합니다.
TV/JPA/ST/DS 같은 약어뿐 아니라 `SERVER:` 뒤의 `Streamtape`, `Mixdrop`, `NinjaStream`
같은 임의의 풀네임도 동적으로 표시합니다. 출처의 `자동`은 StreamTape 계열을 우선하고 사용할 수
없으면 해당 파트의 다른 출처를 순서대로 시도합니다.

설정의 저장소 관리에는 Media Access API의 `prepare-*` 임시 폴더 개수와 용량이
표시됩니다. `찌꺼기 정리`는 실행 중인 작업 폴더를 제외한 중단 작업의 임시 파일을
즉시 삭제합니다. 시작 시 자동 정리는 설정한 보존 시간보다 오래된 임시 폴더만
대상으로 합니다. 자막 번역 기본값은 원문과 번역문이며, 번역 언어는 추천 목록에서
고르거나 Gemma에 지시할 언어 이름을 직접 입력할 수 있습니다.
