# 구매후기

설정 → 기능 → 브라우저에서 확장 ZIP을 받아 압축을 풀고, Chrome의 개발자 모드에서 로드한다. 같은 화면에서 연결 키를 발급해 확장에 Talk 주소와 함께 입력한다. 네이버 로그인과 구매내역은 사용자 Chrome에 유지된다.

Talk에 구매상품 조회를 요청하고 실제 사용 소감·별점을 전달한다. 표시된 초안의 **이대로 등록**을 누르면 최대 10개를 순서대로 처리한다. 서버 별도 설치는 없다.

현재 Chrome의 DOM을 읽으며, 리뷰 메뉴 이동과 최대 4단계 스크롤·DOM 변경 대기로 추가 상품을 수집한다. 빈 상품 목록을 미로딩으로 단정하지 않고 추출 실패·관찰된 로딩을 구분한다. 전체 주문내역 수집 완료를 보장하지 않는다. 상품·입력창·별점을 식별하지 못하면 멈춘다. 완료 문구가 확인되지 않거나 연결이 끊긴 등록은 재시도하지 않고 구매내역에서 확인한다. 실제 네이버 계정의 화면 변화는 현장 확인이 필요하다.

구현: `internal/browserbridge` 및 `internal/server/browser.go`. 업로드된 `naver-review-extension-mvp.zip`의 DOM 입력 방식을 바탕으로 연결·대상 검사·승인·중복 방지를 추가했다. Chrome 테스트는 외부 제출 없는 로컬 페이지로 실행한다.

```sh
TALK_BROWSER_E2E=1 go test ./internal/browserbridge -v
```

확장 0.2.0부터 탐색과 스크롤을 지원한다. 업데이트는 ZIP을 기존 확장 폴더에 덮어쓰고 Chrome 확장 관리에서 새로고침한다. 연결 키 재발급은 필요 없다.

0.3.0: `open`으로 리뷰창을 열고 `fill`로 본문·별점을 실제 입력한다. 입력만 할 때는 등록하지 않는다. `submit`만 최종 등록 승인을 받는다.

0.4.0: 입력창을 확인·수정한 뒤 Talk에 “등록해”라고 하면 현재 내용·별점을 읽어 그대로 등록한다. 추가 승인 버튼과 초안 덮어쓰기가 없다. 읽은 이후 내용이 변경되면 중단한다.

0.5.0: 주문내역·작성 가능한 리뷰 화면의 “쓰기/쓰고/한달사용리뷰” 동작을 인식하고 뒤의 혜택 문구와 분리한다. 진단 텍스트를 상품 목록으로 사용하지 않으며 상품 매칭 실패는 실패로 반환한다.

0.6.0: 입력칸의 조상 영역을 검사해 리뷰창을 찾고, 새 창·주소 변경·발견한 입력칸을 클릭 전후로 기록한다. 새 창 링크는 Chrome 탭 API로 연다. 기존 상세보기 탭과 이번 동작으로 생성된 탭을 구분한다.

0.7.0: 리뷰 버튼은 `chrome.debugger`의 `Input.dispatchMouseEvent`로 누른다. 버튼 위의 가림 요소를 확인하고 클릭 때만 연결한 뒤 해제한다. 기존 DOM click과 구분해 trusted event·user activation 결과를 기록한다. 확장 manifest의 debugger 권한이 필요하다. [Chrome 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/debugger).

0.8.0: Chrome의 popup window 생성·동일 이름 팝업 재사용을 구분하고 windowId를 기록한다. 팝업의 별점·등록은 Chrome 마우스 입력, 본문은 Input.insertText로 입력한다. 별도 팝업 및 재사용 팝업에서 검증했고, 수동 수정 뒤 기존 스냅샷 등록 차단과 수정 내용 그대로 등록도 검증했다.
