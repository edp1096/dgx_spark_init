# Qwen Image 2.1 운영 정책

2026-10-08 운영 QAD TP1은 검증한 **512K(524288토큰)·FP8 KV·MTP 3** 설정을
적용한다. Huihui LIL 체크포인트를 유지하고 단독 Qwen Image DiT·ASR·Qwen3-TTS를
상주시킨다. 이미지 W4A8 TE와 BF16 VAE는 단계별로 해제하며 Extra는 요청 시 실행한다.
운영 바인딩은 `keep_resident: true`, `start_after_llm: true`이며 이미지에
`runtime_options.IMAGE_RESIDENCY: dit`를 지정한다. 다른 세트의 이미지 정책은 유지한다.
기동 순서는 QAD → ASR·TTS → 이미지다. QAD 예산은 적재 중108GiB/상주94GiB,
이미지는 기동7GiB/작업14GiB/추가 작업6GiB로 분리한다.
실험 기록은 [512K·384K DiT 상주 실측](qad-dit-resident-live-20261008.json)에 있다.
운영 적용 후 [실제 재기동·작업 검증](qad512-production-20261008.json)에서
문맥/KV524288, 운영 작업12개, 130초 유휴 후4개 기본 모듈의 동일 PID 유지,
마스크 밖 원본 픽셀 유지와 취소 후 동일 DiT 재사용을 확인했다. 생성2장은
앞선512K 실험과 픽셀이 같다. 작업 중 시스템 가용 최솟값6.997GiB,
즉시 여유 최솟값3.084GiB였다. 호스트 전체 스왑 증가는 피크195.71MiB이며
이 모델만의 사용량으로 귀속하지 않는다.4개 컨테이너는 OOM 없음·컨테이너 스왑0이다.
재사용 가능한 [512K 세트 설정](qad512-resident-set.yaml)도 함께 보관한다.

이하640K 기록은 이전 운영 설정의 검증 이력이다. 당시 QAD TP1은 실제 문맥과 KV 풀을
640K(655360토큰)로 줄였다. 해당 세트 바인딩의
`runtime_options.MAX_MODEL_LEN: "655360"`가 `--context-length`와
`--max-total-tokens`를 함께 적용한다. 기본 프로필이나 별도 TP2/EXL3 설정을
자동으로 변경하지 않으며, 허용 범위는65536~1048576의64 배수다.
저장된 카탈로그의 문맥·설명과 Talk 입력 문맥도640K로 맞췄다.

실제 `/get_server_info`의 문맥·KV655360과 FP8 KV·MTP3을 확인했다.
KV/QSA 풀은13.813→8.634GiB로5.180GiB 줄었다. 전체 가용량은 초기15.273GiB에서
640K 준비 직후 약23.5GiB로 늘었으며 allocator와 주변 호스트 활동도 포함한다.
PLE 파일과 SSD의 모델 파일 크기는 이 KV 설정으로 줄어들지 않는다.

같은 QAD PID를 유지하며 Talk의 실제 이미지 도구·정상 메모리 입장 경로로
1024×1024 펭귄을 생성했다. 도구 전체84.876초, Comfy prompt37.65초였고
출력 크기와 내용을 확인했다. 검증 중 시스템 가용 최솟값15.574GiB,
즉시 여유 최솟값4.187GiB였다. 시스템100ms/GPU·RSS1초 관측이며 두 값을
더하지 않는다. 이미지 프로세스는 운영 Talk의 유휴 타이머에 등록했다.
원자료·PNG: `~/.cache/model-download-jobs/tts-gguf-comparison-20261008/image-request-memory-fix/`.
이하1M 검증 수치는 이전 설정의 기록이다.

2026-10-06 기본 이미지 서비스를 FLUX에서 Qwen Image 2.1로 교체했다.
기존 이미지 슬롯 `flux2`와 세트·호스트 바인딩은 호환성을 위해 유지한다.
화면 이름은 Qwen Image 2.1, 모델은 `qwen-image-2.1-uc-nvfp4`, 컨테이너는
`sparktalk-qwen-image21`, 이미지는 `sparktalk-qwen-image21:nvfp4-int8-v5-dit-resident`이다.
수정된 사용자 체크포인트는 기본 FLUX 마이그레이션의 대상이 아니다.

## 모델과 기능

원본 NVFP4 본체, 원본 W4A8 인코더, BF16 RGBA VAE를 사용한다. 가중치 파일과
리비전·전체 SHA-256은 [prepare_models.py](../../../compose_yaml/qwen-image21/prepare_models.py)에
고정되어 있다. 추가 비전 INT8 압축·인코더 출력 가중치 제외 실험은 적용하지 않았다.
네이티브 참조 캐시는 INT8, 샘플링은 40단계 Euler/simple, CFG 1이다.
기본 동작에서 참조 캐시 OFF를 사용하지 않는다.

네이티브 생성·참조 생성·참조 편집·머리 교체·마스크 편집·아웃페인트·물체 제거·흰 배경·투명 배경을
지원한다. Talk은 선택 입력 최대 4장, API 자체는 최대 10장이다. 머리 교체는 네이티브 참조 편집이며
BFS LoRA 강도나 rembg 옵션은 노출하지 않는다. 마스크 밖 원본 픽셀은 CPU 합성으로 유지한다.
원본 크기 편집은 16메가픽셀 한도다. 아웃페인트의 `preserve_source=true`는 정확한 내부 픽셀을
유지하지만 이음새가 보일 수 있다. 투명 배경은 네이티브 VAE의 알파를 원본 RGB에 적용한다.
모델이 투명도를 생성하지 않으면 성공으로 취급하지 않는다. 참조의 인물 일치·요청한 자세·문자는
응답 이미지의 실제 내용으로 확인해야 한다.

## 메모리와 수명

이미지 작업은 전역 작업 큐를 사용한다. 큐에서 기다리는 Talk 이미지 요청도 사용 수에 포함한다.
작업이 끝나면 다음 작업이 같은 프로세스를 재사용한다. 상주 설정이 없는 세트에서는 마지막 작업 후 2분 동안 요청이 없으면
백엔드의 실제 유휴 시간·실행/대기 수를 확인하고 quiesce 후 Docker 프로세스 전체를 종료한다.
직접 API 작업도 유휴 시간을 갱신한다. 사용 상태를 모르면 종료하지 않고 다시 확인한다.
Talk 재시작 때 기존 프로세스도 타이머에 등록한다.

2026-10-07 EXL3 세트의 이미지·ASR·TTS에는 `keep_resident: true`를 적용했다.
LLM 다음에 기동하고 유휴 타이머와 메모리 압박 회수에서 제외한다. 새 요청의 메모리가
부족하면 상주 모듈을 종료하지 않고 요청을 거절한다. 명시적인 서비스 종료·세트 변경은 가능하다.
이미지는 `SPARKTALK_KEEP_MODELS_LOADED=1`로 Comfy 기본 smart memory를 사용해
재사용 가능한 가중치를 유지한다. 현재 QAD 512K는 별도 DiT 상주 워커를 사용하며
TE·VAE를 각 단계 종료 후 해제한다. 상주 기본 모듈을 자동 유휴 회수하지 않는다.
EXL3 이미지 예산은 전체 24GiB, 상주분 14GiB와 작업 여유 10GiB다. 공통 작업 큐로
이미지·ASR·TTS 작업을 직렬화하므로 세트 예산은 상주분의 합과 가장 큰 작업 여유를 합산한다.

작업 입장 예산은 전체 서비스 14GiB, 추가 작업 여유 하한 10GiB, 기동 예산 2.5GiB다.
선택 입력 2장을 넘으면 장당 1.25GiB를 추가한다. 더 큰 사용자 예산은 유지한다.
기동·작업 전 실제 시스템 여유를 검사하고 부족하면 유휴 보조 서비스를 회수한 뒤 다시 측정한다.
다른 작업에 메모리가 필요하면 상주 설정이 없는 유휴 Qwen Image 2.1도 종료할 수 있다. 실행·대기 이미지 작업은 보호한다.
위14/10/2.5GiB 수치는 기존 요청 시 기동 정책이다. 현재 QAD 512K는 세트 기동 시
단독 Qwen Image 2.1 GPU DiT를 사전 적재한다. 컨테이너 CPU 메모리 상한112GiB와 swap 상한112GiB를 같게 설정했다.
예산은 입장 검사값이며 모든 해상도·참조 수의 실제 최대 피크를 보증하는 수치가 아니다.

QAD를 유지한 새 CUDA 기동은 즉시 Free 10GiB도 검사한다. 기동 시 SHA-256
검사가 약 10GiB의 가중치를 읽어 파일 캐시를 다시 채우므로, 검증이 끝난
고정 이미지 파일에만 `POSIX_FADV_DONTNEED`를 적용한다. 검증은 생략하지 않는다.
그 뒤 큰 Comfy/PyTorch 라이브러리를 불러오기 전에 같은 장치의 CUDA primary
context를 먼저 만든다. 가중치·추론 커널·샘플링은 변경하지 않는다.
이 초기화 순서와 cgroup 조정은 `nvfp4-int8-v4-resident`에도 유지된다.

## 검증

2026-10-07 EXL3 상주 검증에서는 실행 중인 EXL3 PID 1267314를 유지한 채
이미지·ASR·TTS를 기동했다. 1024×1024 생성은 첫 요청 36.71초, 이미지 유휴
131.01초 뒤 다음 요청 27.17초였고 이미지 PID 2235994를 유지했다.
기존 NVFP4/W4A8/BF16 VAE·40단계 샘플링과 INT8 참조 캐시 설정을 유지했다.
ASR·TTS PID도 같은 유휴 구간과 재요청에서 유지됐다. 음성 및 메모리 관측은
[EXL3 상주 검증](tts-lifecycle.md#exl3-상주-검증)에 있다.

QAD 실제 1M KV·MTP 3과 이미지·ASR·TTS를 함께 쓰는 2026-10-06 후속 시험은
[TTS 통합 운영 기록](tts-lifecycle.md#qad-1m-통합-운영-실측)에 있다. 이미지의
새 CUDA 기동·SHA 검사 캐시 반환도 이 시험에서 확인했다.

실제 Talk 도구의 1024px 생성 2회: 최초 56.36초, 연속 28.17초, 동일 이미지 PID 3425738,
두 라운드 모두 호스트 신규 스왑 쓰기 0. 이 시험은 QAD가 꺼진 상태다.
마스크 밖 RGBA와 원본 크기, 아웃페인트 내부 픽셀, 네이티브 알파, 활성·대기·취소·유휴 종료 계약을
CPU 시험으로 확인했다. 사용 중/대기 중/상태 불명/최근 직접 API 작업/새 대기 요청 보호 및
메모리 부족 시 회수는 Go 수명 시험에서 확인했다.
실행 기록은 `~/.cache/model-download-jobs/qwim21-production-20261006/`에 보관한다.

네이티브 API의 참조 생성·참조 편집·인페인트·물체 제거·아웃페인트·머리 교체·흰 배경·투명 배경
8개 경로가 모두 성공했다. 인페인트/물체 제거의 마스크 밖 픽셀과 아웃페인트 내부 픽셀이
원본과 같았고, 배경 제거의 알파 범위는 0..255였다. 직접 동시 API 요청의 대기 수를 확인한 뒤
quiesce가 409를 반환했고 두 결과 모두 같은 PID로 완료됐다. 운영 Talk이 마지막 작업 후
122.86초에 프로세스를 종료했으며, 이 시험의 시스템 가용 메모리는 약 3.99GiB 늘었다.
주변 호스트 활동이 포함된 시스템 차이이며 모든 상황의 반환량을 보증하지 않는다.

종료 후 운영 Talk의 서비스 시작 경로로 다시 기동했고, 다음 실제 Talk 도구 생성이 33.64초에
성공했다. 새 PID는 3460079, 그 라운드의 호스트 스왑 읽기/쓰기는 모두 0이었다.
이 기동의 cgroup `oom`/`oom_kill`/`memory.swap.current`는 모두 0이었다.
생성·편집·동시 요청·재기동 검증에서 나온 PNG 13장은 운영 Talk의
**Qwen Image 2.1 운영 적용·검증 · 2026-10-06** 대화에 저장하고 다운로드 SHA-256을 확인했다.

투명 PNG의 확인을 돕는 흰 배경 합성 미리보기와 알파 마스크 2장도 같은 대화에 보관했다
(모델 원본 13장 + 파생 확인 이미지 2장). 메모리 부족의 즉시 Free 회복 경로는 GPU 없는
모델 준비 이미지로 Qwen Image 2.1의 고정 리비전과 종료된 음성/이전 이미지 가중치 파일만
`POSIX_FADV_DONTNEED`로 조언한다. 실행 중 LLM 체크포인트/KV와 전역 `drop_caches`는
대상이 아니다. 실제 CPU 보조 경로 시험과 캐시 대상 범위 시험도 통과했다.
