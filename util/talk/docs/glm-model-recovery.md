# GLM 가중치 누락 복구

`glm53-exl3`는 실행 코드가 아니라 약 164GiB의 GLM 본체 가중치다. 이 폴더를
삭제하면 모델세트 정의가 남아 있어도 GLM은 시작할 수 없다.

직접 복구하는 절차:

1. GLM 모델세트를 중지한다.
2. **설정 → 시스템 → 모델 준비**에서 GLM과 사용할 가중치 종류를 선택한다.
3. **모델만 준비**를 누른다. 다운로드와 워커 동기화가 끝나면 GLM 세트를 시작한다.

터미널에서는 준비된 GLM 실행 디렉터리에서 `./manage.sh model` 후
`./manage.sh start`를 실행할 수 있다. 이미지까지 없는 환경은 `전체 준비` 또는
`./manage.sh setup`을 사용한다.

시작 전 검사는 양쪽 호스트의 모델 설정, shard 목록, 각 safetensors 헤더와
실제 파일 길이, DFlash2 파일을 검사한다. 누락·잘린 파일은 Docker 컨테이너를
시작하기 전에 복구 경로와 함께 보고한다. 이는 빠른 구조 검사이며 파일 전체의
해시 검사를 대신하지 않는다. 헤드 컨테이너 시작이 실패하면 시작된 워커도 중지한다.

2026-09-13의 오류는 SSD 정리 후 헤드의 `glm53-exl3`만 없어진 경우였다.
워커에 남은 동일 가중치를 고속 연결로 복사해 복구했다.

복사·다운로드 직후에는 가중치가 파일 캐시에 남아 `MemAvailable`은 충분하지만
즉시 쓸 `MemFree`가 적을 수 있다. GLM 시작 작업은 이 종류의 메모리 오류에만
기존 실행 절차의 파일 캐시 반환을 먼저 수행하고 전체 메모리 검사를 다시 한다.
실제 용량 부족은 그대로 거부하며, 상태 조회나 다른 모델 시작에는 적용하지 않는다.

복구 검증: 120개 본체 shard(175,642,157,752바이트)의 SHA-256이 제공된
`SHA256SUMS`와 모두 일치했다. Talk에서 GLM 세트가 준비 완료됐고, 검증 대화의
`4+5` 질문에 `9`를 반환했다. 기존 Abliterated 선택과 DFlash2 설정은 유지했다.
가중치 구조 검사·복구 안내·실제 용량 부족 보호 테스트와 orchestrator/server
테스트가 통과했다.
