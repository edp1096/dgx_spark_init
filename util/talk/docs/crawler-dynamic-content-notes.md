# 동적 페이지 크롤러: 본문 준비 감지와 Shadow DOM 수집

독립 크롤러를 만들 때 재사용할 수 있도록 정리한 문제 해결·구현 메모다. 특정 사이트의 주소, 콘텐츠, 전용 선택자는 포함하지 않는다.

## 1. 재현한 문제

### 페이지 접근 성공과 본문 수집 성공은 다르다

HTTP 200을 받거나 제목·메뉴가 추출됐다는 사실만으로 본문을 확보했다고 판단하면 안 된다. 초기 HTML에는 로딩 문구만 있고, 브라우저에서 비동기 검사와 데이터 요청을 마친 뒤 본문이 표시되는 페이지가 있다.

기존 `auto` 모드는 정적 HTML에서 추출한 텍스트가 300자 이상이면 충분한 내용으로 판단했다. 메뉴가 길면 본문이 비어 있어도 이 조건을 통과했다.

### 렌더링된 본문도 일반 HTML에는 없을 수 있다

`document.documentElement.outerHTML`에는 Shadow DOM 내부가 포함되지 않는다. 열린 Shadow DOM뿐 아니라 닫힌 Shadow DOM을 사용하는 컴포넌트도 있으므로, 브라우저로 페이지를 열었다는 사실만으로 HTML 기반 추출의 한계가 없어지지는 않는다.

### 추출 성공 뒤의 후처리가 전체 요청을 실패시켰다

독립 시험에서는 Shadow DOM 텍스트를 읽고 종료하므로 성공했다. 실제 서비스에는 그 뒤 제목·URL·HTML·스크린샷을 저장하는 단계가 더 있었다.

단계를 나눠 재현한 결과, 다음 순서에서 멈췄다.

```text
DOM.getDocument(depth=-1, pierce=true) → 본문 확보
document.title / location 조회       → 성공
chromedp.OuterHTML("html", ByQuery)   → 제한 시간까지 대기
```

직접 CDP로 DOM을 조회한 뒤 chromedp 선택자가 관리하는 노드 상태를 다시 사용하는 경로에서 문제가 발생했다. 노드 ID·캐시 상태 불일치가 의심되는 지점이며, 내부 원인 전체를 추적한 것은 아니다. 확인된 사실은 위 호출 순서에서 정지했고, 선택자 기반 HTML 조회를 없애자 실제 서비스에서도 완료됐다는 것이다.

## 2. 현재 구현한 수집 흐름

```text
입력 URL 검증
  → 정적 HTTP 수집
  → 콘텐츠 종류·텍스트 길이·로딩 표시 검사
  → 필요하면 격리된 Chromium 실행
  → 페이지 이동
  → 준비 상태를 주기적으로 확인하면서 Shadow DOM 텍스트 추출
  → 선택자 캐시를 거치지 않고 일반 HTML 저장
  → 스크린샷 시도
  → HTML 정규화 결과와 Shadow DOM 텍스트 결합
  → 크기 검사 후 결과 반환
```

`direct` 모드는 정적 수집만 수행한다. `browser` 모드는 브라우저 수집을 바로 수행한다. `auto` 모드는 HTML 텍스트가 길더라도 로딩 표시가 남아 있으면 브라우저로 넘어간다.

## 3. 고정 대기 대신 준비 상태 확인

브라우저에서 200ms 간격으로 DOM을 조회한다. 다음 신호를 함께 본다.

- `aria-busy="true"`가 있는가?
- `Loading`, `Please wait`, `불러오는 중` 등 알려진 로딩 문구가 남아 있는가?
- 작성자가 만든 Shadow DOM에 텍스트가 들어왔는가?
- 일반 페이지의 최소 안정화 시간이 지났는가?

로딩 표시가 사라지고 Shadow DOM 텍스트가 확보되면 즉시 진행한다. Shadow DOM이 없는 일반 페이지는 설정된 안정화 시간 이후 진행한다. 현재 기본 안정화 시간은 1.2초이며, 준비 상태 확인의 최대 대기는 `max(8초, 설정값)`이다. 8초를 항상 기다리는 구조가 아니다.

로딩 문구 판정은 대소문자·주변 공백·끝의 마침표와 말줄임표를 정리한 뒤 알려진 문구와 일치하는지 확인한다. 본문 중간에 `loading`이라는 단어가 있다는 이유만으로 로딩 중이라고 판단하지 않는다.

최대 대기에 도달해도 로딩 표시가 남아 있으면 현재 확보한 내용에 불완전 수집 경고를 붙인다. 본문이 확보됐다고 단정하지 않는다.

이는 규칙 기반 휴리스틱이다. 로딩 표시가 없는 페이지나 숨겨진 로딩 요소를 완벽하게 판별하는 범용 본문 완료 검출기는 아니다.

## 4. Shadow DOM 텍스트 추출

브라우저의 Chrome DevTools Protocol을 사용한다.

```go
root, err := dom.GetDocument().
    WithDepth(-1).
    WithPierce(true).
    Do(ctx)
```

반환된 트리의 `Children`과 `ShadowRoots`를 순회한다. Shadow DOM 안의 텍스트 노드에서 내용을 모으며, 다음은 제외한다.

- `SCRIPT`, `STYLE`, `NOSCRIPT`, `TEMPLATE`
- 브라우저 내부 컨트롤의 `user-agent` Shadow DOM

일반 HTML은 기존 정규화기로 처리하고, 별도로 모은 Shadow DOM 텍스트를 결합한다. 따라서 원시 HTML 파일만 다시 파싱하면 Shadow DOM 텍스트가 복원되지는 않는다. 정규화된 텍스트도 수집 결과의 독립 산출물로 보존해야 한다.

이 방법은 페이지 스크립트를 수정하거나 `attachShadow`를 덮어쓰는 방식이 아니다. 페이지의 검사·로딩 절차는 브라우저가 정상 실행하며, 렌더링된 DOM을 CDP로 조회한다. 로그인·CAPTCHA 같은 접근 요구를 자동 해결하는 기능은 포함하지 않는다.

## 5. HTML 저장 경로와 제한 시간

Shadow DOM 조회 후 일반 HTML을 저장할 때는 chromedp의 선택자 기반 조회를 다시 사용하지 않는다.

```go
chromedp.Evaluate("document.documentElement.outerHTML", &pageHTML)
```

반복문에서 경과 시간을 검사하는 것만으로는 충분하지 않다. 반복문 안의 CDP 호출이나 그 전후 단계가 멈추면 해당 검사를 다시 실행할 수 없기 때문이다. 실제 작업에 전달하는 `context.Context`에도 제한 시간을 적용한다.

| 구간 | 현재 제한 |
|---|---:|
| 브라우저 작업 전체 | 30초, 상위 요청 기한이 더 짧으면 그 기한 |
| 페이지 이동 | 15초 |
| 준비 상태 확인 | `max(8초, 안정화 설정값) + 1초` |
| 제목·URL·HTML 저장 | 3초 |
| 스크린샷 | 3초 |

단계별 제한은 전체 제한 안에서 작동한다. 오류에는 단계 이름과 경과 시간을 넣고, 성공한 단계의 소요 시간도 기록한다. 단순히 `context deadline exceeded`만 반환하면 어느 단계가 문제인지 알 수 없다.

스크린샷은 보조 산출물로 취급한다. 촬영이 실패해도 이미 확보한 텍스트와 HTML은 반환한다. 현재 HTML 저장은 여전히 필수 단계다. 텍스트만으로도 응답할 수 있는 더 세밀한 부분 성공 정책은 향후 분리할 수 있다.

## 6. 검증에서 배운 점

독립 프로그램에서 본문을 읽었다는 사실과 실제 서비스 요청이 끝까지 성공했다는 사실을 구분해야 한다. 다음 범위를 모두 확인한다.

1. 본문 추출 뒤의 HTML 저장·미리보기·직렬화까지 포함한 전체 실행 순서.
2. 운영 환경의 사용자 권한, `HOME`, 읽기 전용 파일시스템, 임시 공간, CPU·메모리 제한.
3. 실제 서비스 API를 호출하는 소비자 경로와 최종 결과.
4. 문자 수뿐 아니라 추출된 내용이 요청한 본문인지 여부.

이번 수정은 실제 대화 도구 경로에서 브라우저 수집과 요약까지 확인했다. 수집 단계는 약 3.7초였고, 멈추던 HTML 저장 단계는 약 12ms에 완료됐다. 이는 한 실행의 관측값이며 성능 보장은 아니다. 전체 대화 응답 시간에는 모델 추론 시간이 별도로 포함된다.

회귀 테스트에는 작성자 Shadow DOM 추출, 스타일·브라우저 내부 Shadow DOM 제외, 로딩 표시 판정, 멈춘 작업의 단계별 시간 제한을 포함했다.

## 7. 독립 프로젝트로 분리할 때

- 브라우저 실행·네트워크 정책, 준비 상태 판정, DOM 추출, 본문 선별, 결과 저장을 별도 구성요소로 나눈다.
- 일반 규칙과 뷰어별 어댑터를 분리한다. 현재 Shadow DOM 대응에는 특정 도메인이나 본문 선택자가 들어가지 않는다.
- 수집 결과에 부분 성공 여부, 경고, 단계별 소요 시간, 실패 단계를 구조화해 반환하면 소비자가 재시도를 판단하기 쉽다. 현재 일부 경고는 텍스트에 포함되어 있다.
- 동일 URL·동일 옵션의 반복 호출을 새로운 전략으로 취급하지 않는다. 현재 도구 설명도 수행하지 않은 스크롤·대기나 무의미한 재시도를 약속하지 않도록 안내한다.
- Shadow DOM 내부의 가시성 판정, 본문 우선순위, 중복 제거, 의미 있는 문단 경계, iframe 처리는 별도 개선 과제다. 현재 텍스트 결합을 완전한 본문 추출 알고리즘으로 간주하지 않는다.
- 기존 URL·리다이렉트·브라우저 하위 요청의 공용 네트워크 검증과 결과 크기 제한을 유지한다.
