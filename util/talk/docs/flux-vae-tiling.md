# 현재 정책

현재는 본체 가중치 유지와 작업 버퍼 반환을 분리한다. [현재 구현과 검증](weights-resident-runtime.md)을 참고한다. 아래는 단계별 언로드를 사용하던 초기 검증 기록이다.

# Flux 부가 모듈 메모리 관리

초기 검증 이미지: `sparktalk-flux2-paint:trial8-phased`. `SPARKTALK_FLUX_PHASED=1`이 기본이며 Talk Compose에도 명시한다.

- 텍스트 인코더는 문장 인코딩 후 작은 CPU 결과 텐서만 남기고 언로드·참조 해제·GC·미사용 CUDA 캐시 반환을 수행한다. 모델 객체가 작업 그래프 캐시에 남지 않는다.
- VAE는 일반 생성과 LanPaint를 포함한 모든 이미지 encode/decode에서 512px 타일·64px 중첩을 사용한다. 확산 모델 자체의 타일링은 아니다.
- Flux 작업 예산은 실측 추가 점유를 바탕으로 5.25GiB다. 강제 상한은 아니며 최소 여유 1.5GiB를 별도로 검사한다. 기존 기본 12/13GiB만 마이그레이션한다.
- Qwen의 가중치·1M 문맥·MTP·프로세스는 유지한다.

## 2026-09-28 검증

1024 생성, 참조 편집, 인페인트, 아웃페인트, 물체 제거, 배경 정리, LoRA+rembg 7개 경로가 통과했다. 시작 가용 10.42GiB, 최저 5.68GiB로 최대 추가 점유는 4.74GiB였다. 기존 512 타일 결과와 같은 시드 일반 생성의 픽셀 차이는 0이었다. 마스크 밖 픽셀과 아웃페인트 원본 보존도 비교했다.

Qwen이 생성 이미지와 7,004토큰 입력을 처리한 뒤 실제 Talk 경로에서 추가 검증했다.

- 가용 7.25GiB 제한 상태에서 거북이 생성 성공, 최저 가용 3.80GiB.
- ASR 선기동으로 가용 5.49GiB인 상태에서 유휴 ASR 회수 → Flux 기동 → 거북이 생성 성공, 최저 가용 3.88GiB.
- 압력용 컨테이너가 OOM으로 사라져 여유가 생긴 결과가 아님을 확인했다.
- 전환 시험 중 CUDA 초기화 실패도 재현했다. MemAvailable과 별도로 즉시 여유 4GiB를 확인하며, 필요 시 종료한 부가 모델의 깨끗한 파일 캐시에만 `POSIX_FADV_DONTNEED`를 적용한다. Qwen 파일·KV와 전역 캐시 설정은 건드리지 않는다.
- 제로 스왑 보장은 아니다. 7.25GiB 제한 시험에서 최대 swap 사용은 약 0.74GiB, ASR 회수 재시험에서는 약 0.31GiB였다.

256 타일과 확산 모델 강제 CPU 이동 시험은 채택하지 않았다. 모든 입력·길이의 최대치를 증명하는 시험은 아니다. 로그·이미지·메모리 샘플은 `~/.cache/runtime-inspection/flux-phased/`에 보관한다.
