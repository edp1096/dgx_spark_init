# ASR 요청별 메모리 예산

2026-10-06부터 ASR 가중치는 Q5_K다. 동일 CUDA 런타임·화자 모델을 유지한 비교에서 고정 모델 버퍼는 Q8 1.63GiB에서 Q5_K 1.22GiB로 감소했다. 한국어 FLEURS 100개(1,225.74초)의 문자 오류율은 Q8 8.63%, Q5_K 8.50%, 평균 API 지연은 70ms·71ms였다. 이 표본의 작은 차이를 정확도 향상으로 판정하지 않는다.

10분 전사 시험의 추가 RAM 피크는 Q8 약 3.85–3.97GiB, Q5_K 약 3.70GiB였다. 고정 버퍼 절감량과 시스템 전체 여유 변화는 같은 값이 아니다. 아래 길이별 작업·기동 예산은 긴 음성의 실행 버퍼를 위해 보수적으로 유지하며, 이미 상주한 서비스의 실제 점유는 요청 잔여 예산에서 차감한다.

운영 파일은 528,061,920바이트이며 SHA-256은 `f0dab30ca22a606c2ab9a65efae88421851c6ca4ab01160708ab733b4467ce58`이다. 재설치 시 고정된 공식 Q8·NeMo 원본을 준비하고 CPU에서 변환한다. 기존의 검증된 F16 파일이 있으면 재사용하며, 변환 결과를 검증한 뒤 원자적으로 교체한다.

2026-10-06 운영 적용 검증: 새 CPU 변환 이미지에서 F16 캐시 없이 공식 원본만으로 같은 SHA-256을 재현했다. 운영 CUDA 이미지의 한국어 100개 전사 결과는 사전 검증한 Q5_K 결과와 모두 일치했다. Talk의 WAV·WebM 음성 입력을 확인했으며, 유휴 ASR 컨테이너를 제거한 뒤 음성 요청으로 자동 재생성해도 Q5_K를 사용했다. 2분 첨부 음성의 전사·화자 구분도 완료했다. 이 검증은 Q5_K의 1시간 음성이나 언어 모델과의 동시 상주 피크를 보증하지 않으므로 기존 예산을 유지한다.

예산 측정 당시 `sparktalk-nemotron-asr:0.6b-q8-diar1` 구성의 기동 예산은 3.5GiB다. 기존 카탈로그의 6GiB는 입력을 모르는 경우의 기본 추정치로 남지만, Talk의 음성 입력·첨부 전사는 이 값을 일괄 적용하지 않는다.

1. Extra Media만 준비해 음성을 16kHz mono PCM16 WAV로 추출한다.
2. 최대 512MiB의 임시 파일로 받아 실제 추출 크기를 확인한다. 압축된 업로드 크기로 길이를 추정하지 않는다. 파일은 성공·실패 모두 삭제한다.
3. 추출 작업의 대기열 점유를 반환한 뒤 ASR 작업 예산으로 다시 대기열에 진입한다. ASR과 Media의 예산을 검사하고, 필요한 경우 유휴 FLUX를 회수한다. 실행 중인 다른 작업을 중지하지 않는다.
4. ASR 예산은 `ceil((3.75 + WAV바이트×32/2^30 + 화자구분여유)×4)/4` GiB다. 화자 구분 여유는 0.25GiB다. 추출 파일 크기·요청 모드를 사용하고, 기본값보다 큰 사용자 예산은 유지한다.
5. 이미 상주한 ASR/Media 점유는 잔여 필요량에서 차감한다. 성공 후 여유가 있으면 재사용하고 오류·취소 시에는 정리한다.

| 음성 길이 | 일반 전사 예산 | 화자 구분 포함 예산 |
|---|---:|---:|
| 2분 | 4.00GiB | 4.25GiB |
| 10분 | 4.50GiB | 4.75GiB |
| 1시간 | 7.25GiB | 7.50GiB |

이는 실측에 여유를 더한 예산이며 강제 메모리 상한은 아니다. 파일 크기에 비례해 증가하며 6GiB에서 잘라내지 않는다. 다른 ASR 구성에는 이 프로필을 적용하지 않는다.

## 측정 근거 — 2026-09-28

동일 Q8 ASR + Nemotron-3-Diarization 서버에서 공개 JFK 샘플을 반복한 30초·2분·10분·1시간 WAV를 순차 처리했다. 모든 전사/화자 API가 HTTP 200을 반환했다. GPU 프로세스와 비회수 호스트 상주량을 약 0.5초 간격으로 관측했다.

- 2분 전사 관측 피크: 3.83GiB.
- 10분 전사: 4.22GiB, 화자 구분: 4.18GiB.
- 1시간 전사: 6.97GiB, 화자 구분: 6.53GiB.
- 30초 처리 시간은 샘플 간격보다 짧아 그 구간의 피크를 확정하지 않았다.
- 1시간 일반 전사는 약 112초, 화자 구분은 약 12.5초였다.
- 스왑 증가는 관측됐다. 제로 스왑이나 모든 내용·화자 수의 피크를 검증한 결과가 아니다.

원시 기록: `~/.cache/runtime-inspection/asr-profile/`. 긴 오디오 API는 전체 업로드/float 음성 버퍼를 보유하며, ASR은 모델 위치 한계를 넘으면 내부 스트리밍 경로를 사용한다. 그래서 모델 파일 크기만으로 예산을 정할 수 없다.

Talk 실서비스 경로 검증: 1시간 MP3 입력을 추출해 전사·화자 구분 완료(127.8초, 텍스트 34,943바이트). 이어서 11초 음성 2회도 완료(1.68초/1.60초), ASR 컨테이너 PID 1062036 유지. 이 검증 전후 Qwen PID 1094479 유지. Go ASR/server/orchestrator/config race 테스트와 웹 빌드 통과.

후속 이미지 `0.6b-q8-diar2-workspace`는 가중치를 유지하고 요청 후 그래프 버퍼를 반환한다. 기존 길이별 예산은 낮추지 않았다. [후속 기록](weights-resident-runtime.md).

## v0.2.0 운영 갱신 — 2026-10-08

운영 엔진을 공식 v0.2.0 커밋 `6a3ca369370782acee0dd155e34394ba60b920c4`로
갱신했다. 배포 이미지 버전은 `sparktalk-nemotron-asr:0.1.0`이며 엔진 버전과 구분한다.
이전 엔진은 v0.1.0을 표시하는 2026-09-24 커밋이었다.

공식 `llama.cpp/ggml` 0.25.1과 업스트림의 configure 패치를 사용한다. 자체 런타임
패치는 가중치를 유지하면서 요청 작업 공간을 반환하는 `release_workspace.py` 하나다.
같은 소스·컴파일 설정의 순정과 비교해 이 패치의 효과를 확인한 뒤 유지했다.

| 긴 요청 후 유휴 점유 | v0.2.0 순정 | v0.2.0 + 작업 공간 반환 |
|---|---:|---:|
| GPU 프로세스 | 2.180 GiB | 1.636 GiB |
| cgroup 익명 메모리 | 1.205 GiB | 1.049 GiB |

통합 메모리 환경이므로 위 GPU·호스트 값을 단순 합산하지 않는다. 기존 길이별 작업
예산은 낮추지 않았다. 관측한 컨테이너 스왑은 모두 0, OOM은 없었으며, 전역 호스트
스왑 점유 피크 증가는 순정 2.66 MiB·패치판 0.32 MiB였다.

한국어 100개 문자 오류율은 이전 운영판·새 순정·새 패치판 모두 8.50%였다.
한국어 추가 20개와 영어·일본어·중국어 각 10개를 포함한 150건은 전사 문자열이 모두
일치했다. 새 순정·패치판의 응답은 단어 타임스탬프까지 같았고, 10분 전사·실제 두
화자 구분·10분 화자 구분 응답도 같았다. 추가 한국어 표본은 100개 표본과 일부
겹치므로 120개 독립 표본으로 해석하지 않는다.

새 ggml 양자화기로 F16 캐시에서 Q5_K를 재생성해 기존 SHA-256을 재현했다.
새 변환기의 OpenMP 라이브러리 의존성(`libgomp1`)도 반영했고, 설치 도구 이미지가
이전 변환기를 재사용하지 않도록 v0.2.0 소스 커밋으로 고정했다. 모델 재다운로드는
없었다. Talk 마이크 API와 AAC MP4 첨부의 전사·화자 구분을 확인했다.

시험 중 기존 EXL3·QWIM/MMH3·TTS는 계속 상주했다. 순정 시험 일부는 C++ 증분
빌드와 겹쳤으므로 지연 시간으로 성능 우열을 단정하지 않는다.
[원시 수치·운영 검증 기록](nemotron-v020-production-20261008.json).

운영 교체 후 130초 유휴 확인에서도 ASR·EXL3·QWIM/MMH3·TTS의 컨테이너와
PID를 유지했다. 이 구간에서 OOM과 스왑 점유 증가는 없었다. ASR 유휴 GPU는
1.554 GiB, cgroup 익명 메모리는 0.833 GiB였다. 앞 표는 동일한 10분 비교 입력 뒤의
관측치이고, 이 값은 운영에서 짧은 음성·영상 입력 뒤의 관측치로 조건이 다르다.
