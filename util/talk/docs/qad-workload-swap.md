# QAD 작업 서비스 교대 실행

QAD TP1의 `workload_swap: true`는 Qwen을 유지하면서 다음 두 작업 구성을 교대로 실행한다.

- 이미지: Flux (생성·편집·인페인트·아웃페인트·배경 처리 공통 도구 경로)
- 음성·미디어: ASR + Extra Media. 다운로드·프레임 추출만 요청하면 Media만 시작한다.

요청은 공통 대기열을 거친다. 먼저 현재 여유와 요청 서비스의 추가 필요량을 검사하고, 부족하면 유휴 경쟁 서비스를 회수한 뒤 다시 검사한다. 이미 상주한 요청 서비스의 메모리를 기동 예산에 중복 합산하지 않는다. 작업 성공 후 최소 여유가 남으면 컨테이너를 유지해 다음 요청에서 재사용한다. 여유 부족·작업 실패·취소 시에는 컨테이너를 중지한다. 취소된 대기 요청은 서비스를 시작하지 않는다. 실제 요청이 취소되면 독립된 정리 컨텍스트로 컨테이너를 종료한다. 종료 실패 시 다음 작업을 시작하지 않는다. 실행 중 수동 모델 전환·서비스 중지는 거부한다.

기동 예산은 Qwen + max(Flux, ASR 기본 예산 + Media)로 계산한다. ASR 전사는 추출된 음성 크기와 화자 구분 여부로 작업 예산을 다시 산정한다([산정과 실측](asr-memory-budget.md)). 각 작업 직전에도 실제 MemAvailable·즉시 여유를 확인한다. Qwen 1M 문맥·MTP·최소 여유 설정은 바꾸지 않는다.

작업 서비스는 세트 기동 시 상주하지 않고 화면에 ‘요청 시 실행’으로 표시된다. 재기동 비용 때문에 작업 시작이 느려질 수 있다. 기능 사용 여부와 세트 구성원은 그대로 보존한다. Talk를 통하지 않는 외부 직접 API 호출에는 이 대기열이 적용되지 않는다.

검증: 일반 테스트와 명시적 실서비스 테스트 `TestWorkloadSwapLive`를 구분한다. 실서비스 테스트는 `SPARKTALK_WORKLOAD_LIVE_CONFIG`, `SPARKTALK_WORKLOAD_LIVE_AUDIO` 지정이 필요하며 실행 시 로컬 작업 컨테이너를 시작·중지한다.

## 2026-09-28 초기 검증 (작업마다 종료하던 구현)

- Go 전체 테스트, 관련 패키지 race 검사, 웹 테스트 106건 및 빌드 통과.
- 실제 QAD 1,048,576 KV 용량·MTP 3단계 유지. Qwen PID 137009 유지.
- 1024 이미지 생성과 한국어 ASR·화자 구분을 동시에 요청하는 시험 2회 통과.
- 1초 간격 148개 샘플에서 Flux와 ASR/Media 동시 실행 0회. 최소 MemAvailable 8.89 GiB, 최대 swap 사용 약 36 KiB. 제로 스왑 검증으로 해석하지 않는다.
- 작업 종료 후 Flux·ASR·Media 중지 확인. 이미지 작업 중 Qwen 계산 응답 `42` 확인.
- 짧은 한국어 음성과 일반 생성의 반복 실행 결과이며 모든 길이·모든 이미지 편집 부하의 최대치를 증명하는 시험은 아니다. 기존 Flux/ASR 예산을 낮추지 않았다.

## 상주량 계산과 재사용 수정

- 로컬 모델의 상주량은 GPU 프로세스 점유 + cgroup `anon + shmem + kernel - slab_reclaimable`로 집계한다. 일반 파일 캐시는 제외하며 cgroup `memory.current` 전체를 더하지 않는다. GPU 집계가 제공되지 않는 외부/원격 모델에는 로컬 총량을 만들어 넣지 않는다.
- 실행 시 이미 올라간 부가 서비스의 잔여 예산을 계산할 때도 같은 호스트 상주량 함수를 사용한다. 서비스 회수 이후 실제 시스템 가용량을 다시 읽는다.
- 현재 Huihui LIL QAD TP1/MTP의 기동 예산은 GPU 약 99.1GiB + 호스트 약 8GiB 관측을 반영한 108GiB다. 강제 상한이나 모든 입력의 피크가 아니다. MTP 미사용 구성과 다른 모델의 기존 프로필은 변경하지 않았다.
- 실행 중 모델이 예산보다 커지면 세트 표시 예산에도 관측 증가분을 반영한다. 부가 모델을 여러 개 유지하면 현재 상주 합계를 교대 실행 예산보다 작게 표시하지 않는다.
- 긴 Qwen prefill·비전 요청의 최대 추가 버퍼는 이번 수정에서 새로 측정한 것이 아니다. 시스템 가용량은 현재 점유를 반영하지만 미래 피크를 보장하지 않는다.

수정 후 검증: 관련 Go race 테스트 통과, 웹 빌드 통과. 서로 다른 seed의 1024 이미지 2회는 50.55초 / 9.65초, Flux PID 1036333 유지. Qwen PID 137009 유지. 배포 후 API에서 Qwen GPU 99.09 + 호스트 7.89 = 상주 106.97GiB, 기동 예산 108GiB, 세트 예산 114.1GiB 확인. 로그는 `~/.cache/runtime-inspection/resident-reuse/`에 보관했다. 이번 추가 실서비스 시험은 이미지 재사용이며 ASR 재사용과 긴 Qwen 입력 피크는 새로 실측하지 않았다.
